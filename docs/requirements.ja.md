# HyperPlot 要件定義 v1

何を作るか、どこまでを v1 とするか、何をもって満たしたとするかを記す。どう作るかは [design.ja.md](./design.ja.md)、順序と状態は [roadmap.md](./roadmap.md) にある。要件を変えるときは `design` Issue で本書を先に直す（`.cursor/rules/design-docs.mdc`）。

数値の目標のうち「仮説」と書いたものは、実測の前に置いた値である。最初の計測の行で参照機と測り方を固定し、そこで値を確定するか直す。

## 1. 目的

C# / .NET から使う、次の 4 つを同時に満たすプロットライブラリを作る。

1. **NativeAOT**: ライブラリ本体（データ・GoG・描画）は trim / AOT の警告ゼロで NativeAOT のアプリに組み込める
2. **ビリオン級の高速描画**: 10 億点の時系列・散布図を、ズーム・パン中も 60 fps で操作できる（SciChart と同じ水準を目標にする）
3. **GoG の柔軟な構成**: Grammar of Graphics（ggplot2・Vega-Lite の考え方）で、データ・エンコーディング・スケール・座標系・Geom・Stat・ファセット・レイヤーを組み合わせてプロットを宣言できる
4. **高度なインタラクション**: ズーム・パン・ホバー・選択・ブラッシングとリンク・注釈・計測を、データ量によらず遅延なく行える

先行の POC（`HighPerfPlotPOC`、Silk.NET / OpenGL、100 万点）は、GPU インスタンシングと層ごとの差分描画で 100 万点が 60 fps で動くことを確かめた。本プロジェクトはその知見を引き継ぎ、規模を 3 桁上げ、製品として作り直す。

## 2. 利用者と用途

| 利用者 | 用途 | 典型のデータ |
| --- | --- | --- |
| 計測・制御アプリの開発者 | オシロスコープ・ロガー・試験装置のビューア | 数 ch × 1e8〜1e9 サンプルの等間隔時系列。追記しながら表示する |
| 科学技術計算の開発者 | シミュレーション結果・解析結果の可視化 | 1e7〜1e9 点の散布図、ヒートマップ、多系列の折れ線 |
| 業務・分析アプリの開発者 | ダッシュボード、探索的な分析 | 1e3〜1e7 行の表形式データ。カテゴリ・ファセット・凡例が多い |

## 3. 対象プラットフォームと提供順

| 順 | ホスト | OS | NativeAOT |
| --- | --- | --- | --- |
| 1 | WPF | Windows 10 1809 以降 | WPF 自体が NativeAOT に対応しないため、WPF のアダプタは JIT で動く。コアと描画は AOT 互換のまま |
| 2 | XylemUI（オーナーの GUI フレームワーク） | Windows（XylemUI の対応 OS に従って拡大） | 対応 |
| — | **v1 公開**（NuGet） | | |
| 3 | Avalonia | Windows → macOS / Linux | 対応 |

- GPU は Windows で Direct3D 11（機能レベル 11_0 以上。compute shader を使う）。WARP（ソフトウェアのラスタライザ）でも動くことを要件にする。VM・リモートデスクトップ・CI で動かすためである
- macOS（Metal）と Linux（wgpu-native）の描画は v1 の後の行とする。ただし v1 の内部設計は、バックエンドを足すだけで対応できる形にする（§6 の N-6）
- ヘッドレス描画（ウィンドウなしで画像を得る）は全ホストより先に用意する。テストと画像出力に使う

## 4. 機能要件

### 4.1 データ

| ID | 要件 |
| --- | --- |
| D-1 | 列指向（SoA）でデータを持つ。型は `float`・`double`・`int`・`long`・`byte`・`DateTime` 相当（`long` のティック）・カテゴリ（辞書符号化した `int`） |
| D-2 | 列の実体を、マネージド配列・ネイティブメモリ・メモリマップしたファイルから選べる。10 億点の列を RAM にすべて読まずに扱える |
| D-3 | 利用者の配列を写さずに列として包める（ゼロコピー）。写す場合はそれを API 上で明示する |
| D-4 | X が単調増加の列（時系列）と、そうでない列（散布）を区別し、それぞれに合う索引を作る |
| D-5 | 等間隔の X（開始値と刻み）を、列を持たずに表せる |
| D-6 | 列の末尾への追記（ストリーミング）と、固定長のリングバッファ（古い点を捨てる）に対応する。追記中も表示とインタラクションを止めない |
| D-7 | 欠損値（NaN、または有効ビット）を扱い、折れ線を欠損で切る |
| D-8 | データの読み込み（CSV・バイナリ）は v1 では最小限とする。ライブラリの責務は列を受け取ることで、ファイル形式の網羅はしない |

### 4.2 Grammar of Graphics

| ID | 要件 |
| --- | --- |
| G-1 | プロットを「データ・レイヤー（Geom・Stat・Position・エンコーディング）・スケール・座標系・ファセット・ガイド・テーマ・インタラクション」の組で宣言する |
| G-2 | エンコーディングのチャネル: `x`・`y`・`x2`・`y2`・`color`・`fill`・`size`・`shape`・`opacity`・`group`・`detail`・`text`・`tooltip` |
| G-3 | Geom（v1）: point・line・step・area・bar（column）・rect（tile / heatmap）・rule（hline / vline）・segment・errorbar・band・text・image（ラスタ） |
| G-4 | Stat（v1）: identity・bin（1D / 2D）・count・summary（mean・min・max・quantile）・density（KDE、1D）・smooth（移動平均）。大規模データ向けの集約（M4・密度）は Stat と同じ枠で表すが、ビューに応じて描画層が自動で選ぶ |
| G-5 | Position: identity・stack・dodge・fill |
| G-6 | スケール: linear・log・symlog・sqrt・power・time（日時）・band / point（カテゴリ）・ordinal・sequential / diverging（色）。domain・range・nice・zero・reverse・clamp を指定できる |
| G-7 | 座標系: cartesian（x と y の入れ替えを含む）・polar。cartesian はビリオン級の経路に対応し、polar は 1e7 点までとする |
| G-8 | ファセット: wrap と grid。軸の共有（shared / free）。ファセットのセルごとにビューを持ち、リンクできる |
| G-9 | 複数レイヤーの重ね合わせ、二次軸（右の y 軸など）、複数のプロットを並べた構成（concat・subplots） |
| G-10 | ガイド: 軸（目盛り・ラベル・グリッド・タイトル）、凡例（離散・連続のカラーバー）、タイトル・注記。目盛りはスケールの種類に合わせて自動で決め、日時軸は粒度（年〜ナノ秒）を切り替える |
| G-11 | テーマ: 色・フォント・線幅・余白をまとめて差し替えられる。ライトとダークの既定テーマを持つ |
| G-12 | 宣言は型安全な C# の API で書く。列は型付きの参照で指し、文字列の列名も使える。リフレクションと実行時のコード生成を使わない |
| G-13 | 宣言を変えたら、変わった部分だけを再計算する（データ・スケール・見た目のどれが変わったかで経路を分ける） |
| G-14 | プロットの種類の拡充: Plotly・matplotlib・ggplot2 など広く使われるライブラリで一般的なプロットの種類を、v1 の後も 2D・3D とも随時足していく。足すたびにロードマップの行を作る。G-3・G-4 と §4.6 の一覧は v1・v1.x で最初に入れる分で、上限ではない |

### 4.3 描画

| ID | 要件 |
| --- | --- |
| R-1 | 1 フレームに GPU へ送る量を、データの点数ではなく画面の画素数で抑える（10 億点でも 1 フレームの転送は数 MB 以下） |
| R-2 | 時系列の折れ線は、画素の列ごとの first・last・min・max（M4）で間引き、間引かない場合と見た目が同じになる（ピーク・外れ値を落とさない） |
| R-3 | 散布図は、画面上の点が閾値を超えるとき密度（2D ヒストグラム）を色で表し、閾値以下になるまでズームすると生の点を描く。切り替えは利用者が無効にもできる |
| R-4 | アンチエイリアスした線（太さ・破線・結合）と、形・大きさ・色を点ごとに変えられるマーカー |
| R-5 | 背景・グリッド・データ・インタラクション・オーバーレイを層に分け、マウス移動では重いデータ層を描き直さない（POC の差分描画を引き継ぐ） |
| R-6 | 倍精度の座標（日時のティック、遠い原点）を深くズームしても、点の位置が画素単位で崩れない |
| R-7 | 軸ラベル・凡例・ツールチップの文字をライブラリ自身が描く（ホストの UI に頼らない）。日本語を含む |
| R-8 | 画像出力（PNG）とヘッドレス描画。出力の解像度を画面と別に指定できる |
| R-9 | 高 DPI とモニタ間の DPI 変更に追従する |

### 4.4 インタラクション

| ID | 要件 |
| --- | --- |
| I-1 | ビュー操作: ホイールズーム（カーソル位置中心）、ドラッグでパン、矩形ズーム、軸上のドラッグで片軸のみの操作、ダブルクリックで全体表示、ズーム履歴の戻る・進む |
| I-2 | ホバー: 最近傍の点（X のみ・XY）、系列ごとの値の読み取り、クロスヘア、ツールチップ。10 億点でも 1 ms 以内に答える |
| I-3 | 選択: クリック・矩形・投げ縄・X 範囲（ブラシ）。選択した点の索引の集合を API で得られる |
| I-4 | リンク: 複数のプロット・ファセットの間で、ビュー範囲・カーソル・選択を共有する（Vega-Lite の selection / param に当たるもの） |
| I-5 | 注釈: 線・矩形・テキスト・マーカーを置き、ドラッグで動かせる。データ座標に固定するか画面座標に固定するかを選べる |
| I-6 | 計測ツール: 2 点間の差分（Δx・Δy・傾き）、範囲内の統計（件数・平均・最小・最大） |
| I-7 | キーボード操作（矢印でパン、+/- でズーム、Esc で選択解除）と、操作の割り当ての変更 |
| I-8 | ジェスチャ（タッチパッドのピンチ・2 本指スクロール）と慣性スクロールは、ホストが渡す入力に応じて対応する |
| I-9 | インタラクションの状態（ビュー・選択・カーソル）はイベントで通知し、コードからも同じ操作を行える。操作のすべてをテストから入力の列として再現できる |

### 4.5 ホスト統合

| ID | 要件 |
| --- | --- |
| H-1 | コア・描画はどの UI フレームワークにも依存しない。ホストのアダプタは「描画先・入力・DPI・フレームの時機」を渡す薄い層とする |
| H-2 | WPF: `HyperPlotView` コントロール。WPF の要素をプロットの上に重ねて置ける（子 HWND を使う方式は採らない）。XAML とコードの両方から使える |
| H-3 | WPF がソフトウェア描画に落ちたとき（リモートデスクトップの一部の構成など）も表示が止まらない |
| H-4 | XylemUI・Avalonia のアダプタは、WPF と同じホスト契約で作る |

### 4.6 3D（v1.x）

v1 では実装しない。v1 の後の版（v1.x）で入れる。v1 の公開 API は、3D を足しても壊れない形にする（N-11、設計書 §13）。

| ID | 要件 |
| --- | --- |
| K-1 | 3D の座標系とカメラ: 透視と正射影、オービット（ターンテーブル）・パン・ズーム、決まった視点（上・前・横・等角）、軸の箱（目盛り・ラベル・グリッドの面）。x・y・z のスケールは G-6 と同じ種類 |
| K-2 | 散布（点群）: x・y・z と color・size・opacity のエンコーディング。10 億点を八分木の LOD で描き、1 フレームに描く点の数に上限（点の予算）を設ける。視点が止まったら細かい節点まで描き足す |
| K-3 | 線（軌跡）: 3D の折れ線。画面上の誤差に上限を決めた間引きで、1e8 頂点まで |
| K-4 | 面: z = f(x, y) の格子（等間隔と非等間隔）。色の写像、ワイヤーフレーム、等高線の投影。格子の LOD で 1e8 セルまで |
| K-5 | メッシュ: 任意の三角形メッシュ（法線・頂点の色・陰影）。1e7 三角形まで |
| K-6 | ボリューム: 3 次元の格子のボリュームレンダリング（伝達関数）、断面、等値面（ワーカーで抽出）。1024³ までをブロックに分けて置く |
| K-7 | 3D のインタラクション: レイでのヒットテスト（点・線・面・メッシュ）、画面上の矩形と投げ縄による選択、2D と 3D のプロットの間のリンク（選択とカーソルの共有） |
| K-8 | 半透明: 密な点と面の半透明を、描く順によらない方法で合成する |

## 5. 性能要件

参照機は最初の計測の行で固定する（暫定: 8 コア以上の x64 CPU、32 GB RAM、NVMe SSD、ディスクリートの GPU。最低限の動作確認は WARP で行う）。値は Release・NativeAOT のヘッドレス描画で測る。

| ID | 場面 | 目標（仮説） |
| --- | --- | --- |
| P-1 | 1e9 点の等間隔時系列（float32、メモリマップ）のズーム・パン | 1 フレームの CPU と GPU の時間がそれぞれ p95 で 8 ms 以下（60 fps を保つ） |
| P-2 | 1e9 点の時系列の LOD 索引の構築 | 1 GB/s 以上（8 コア）。構築中も粗い表示と操作ができる |
| P-3 | 1e9 点の散布図（float32 x, y）の密度表示のズーム・パン | 1 フレーム p95 で 16 ms 以下。生の点を描くのは画面内が 1e7 点以下のとき |
| P-4 | 1e7 点の散布図を生の点で描く | 60 fps |
| P-5 | ホバーのヒットテスト（1e9 点） | p99 で 1 ms 以下 |
| P-6 | マウス移動だけのフレーム（データ層を描き直さない） | 1 フレーム p95 で 2 ms 以下 |
| P-7 | ストリーミング: 合計 1e7 点/秒の追記を 16 系列で | 追記しながら 60 fps。追記から表示までの遅れは 2 フレーム以内 |
| P-8 | LOD 索引のメモリ | 元データの 10% 以下 |
| P-9 | フレームの経路のマネージドアロケーション | 0 バイト（定常状態） |
| P-10 | NativeAOT のサンプル（ヘッドレス描画、WPF なし）の実行ファイル | 仮説 10 MB 以下。最初の AOT の行で実測して確定する |

3D（v1.x、§4.6）の目標は、3D の設計の行（ロードマップ K0）で確定する。今の仮説は次のとおり。

| ID | 場面 | 目標（仮説） |
| --- | --- | --- |
| P-11 | 1e9 点の 3D 散布の回転（点の予算 1e7） | 1 フレーム p95 で 16 ms 以下 |
| P-12 | 1e8 セルの面の回転 | 60 fps |
| P-13 | 1e7 三角形のメッシュの回転 | 60 fps |
| P-14 | 512³ のボリュームの回転 | 30 fps |

## 6. 非機能要件

| ID | 要件 |
| --- | --- |
| N-1 | src のライブラリは `IsAotCompatible`。trim / AOT の警告はビルドエラー。WPF のアダプタだけは WPF の制約で AOT の対象外とし、自身のコードはリフレクションを使わない |
| N-2 | 外部依存は設計書 §0 の基準（AOT・単一バイナリ・ホットパスの制御・ライセンス）を満たすものだけ。Windows で追加のネイティブ DLL を配布しない |
| N-3 | ライセンスは MIT。依存も MIT と両立するもの |
| N-4 | 公開 API には英語の XML ドキュメントを付け、破壊的な変更は v1 以降 SemVer に従う |
| N-5 | テスト: 単体テスト、描画結果のゴールデン画像（WARP）、インタラクションの再現テスト、ゼロアロケーションのテスト。CI は Windows でマージの条件、Linux でもコアのテストを回す |
| N-6 | 拡張性: GPU のバックエンド・ホスト・Geom・Stat・スケールを、コアを書き換えずに足せる |
| N-7 | 決定論: 同じ入力（データ・宣言・入力の列・時刻）から同じ画素が出る（WARP 上） |
| N-8 | スレッド: UI スレッドを O(N) の処理で止めない。重い処理はワーカーで行い、結果に版を付けて受け渡す |
| N-9 | デバイスの喪失（GPU のリセット・ドライバの更新）から復帰する |
| N-10 | アクセシビリティ: v1 はプロットの要約（タイトル・軸・系列）をホストのアクセシビリティ API に渡す。点ごとの読み上げは対象外 |
| N-11 | 3D への備え: 座標系・ビュー・描画 IR・ヒットテスト・空間索引の契約は、2 次元を前提にした型を公開 API に出さない。v1.x の 3D（§4.6）は、v1 の公開 API を変えずに足せる |

## 7. v1 の対象外

- 3D プロットの実装（§4.6 のとおり v1.x で入れる。v1 は N-11 の備えだけを持つ）
- 地図の投影と地図タイル
- Web（Blazor / WebAssembly）への出力
- PDF / SVG のベクタ出力（PNG のみ）
- 印刷
- ファイル形式の網羅（Parquet・HDF5 などの読み込み）
- macOS / Linux の描画バックエンド（v1 の後の行）

## 8. 受け入れ

v1 を公開する条件は次のとおり。

1. §4 の機能要件が、WPF と XylemUI のサンプル（`samples/`）とテストで示されている
2. §5 の性能要件が、`benchmarks/` の計測で参照機の値として `docs/benchmarks/` に記録されている。仮説を直した場合はその理由が ADR にある
3. NativeAOT のサンプルが警告ゼロで公開でき、そのサイズが記録されている
4. `./build.ps1` が Windows で通り、CI が緑である
