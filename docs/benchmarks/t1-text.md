# T1: テキストの計測

行 T1（Issue #104）の計測の記録。設計書 §5.6 のテキスト（DirectWrite の整形とラスタライズ、グリフのアトラス、グリフのパイプライン）を、要件 §5 の参照機で測った。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス。測った後に消した） |
| 描画先 | 1,920 × 1,080（`B8G8R8A8_UNORM`）、ハードウェア |
| ラベル | "-12.50" から "12.25" まで 0.25 刻みの 100 個（5〜6 文字）。Segoe UI、13 画素、中央揃え、上揃え。20 列 × 5 行に並べる |
| CPU | 論理プロセッサ 2 に固定、優先度 High（`bench.mdc`）。各フレームの前に 1 × 1 の描画先の `ReadPixels` で GPU を待つ（待つ時間は測る範囲の外） |
| GPU | `IGpuBackend.LastFrameTime`（タイムスタンプのクエリ、数フレーム後に読む）。クロックは `nvidia-smi --query-gpu=timestamp,clocks.gr,pstate -lms 200` で記録 |

## CPU: キャッシュ済みの 100 個のラベル

1 回目の `Draw` で整形とアトラスが温まった後、1,200 フレーム（最初の 30 フレームは捨てる）。ラベルあり・なしを交互に 3 回。

| 場面 | 記録（中央値 / p95） | `Draw`（中央値 / p95） |
| --- | --- | --- |
| 100 個のラベル | 2.2〜2.3 / 2.4〜2.6 µs | 22.8〜25.4 / 25.0〜31.0 µs |
| ラベルなし | 0.0 / 0.1 µs | 0.2 / 0.3 µs |

- `Draw` の 23〜25 µs は、`TextEngine.Prepare`（100 個の整形のキャッシュの検索、約 500 グリフのアトラスの検索と配置の計算）と、グリフの記録の書き込みと、1 回の `DrawInstanced` である。100 個のラベルは同じ頁と切り抜きなので、1 つの段にまとまる
- 確保は 0 バイト（テストの `HundredLabels_Warm_AllocateNothing`、偽のバックエンドと DirectWrite の両方）

### フレームの開閉の時間（T1 の外）

同じ測り方で、`BeginFrame` が 81〜102 µs、`FrameScope.Dispose`（`EndFrame`）が 249〜276 µs かかった。ラベルの有無で変わらない。GPU を待たずに続けて描いても同じだった。プロセスを固定しないで測ると、`BeginFrame` は 0.3 µs、`EndFrame` は 14〜19 µs になった。プロセスの固定はスレッドすべてに当たるので、GPU のドライバが命令の送信に使うスレッドも同じ論理プロセッサに乗り、タイムスタンプのクエリと `Flush`（行 S2、設計書 §5.3）がそのスレッドを待つためと考えられる。どちらの測り方でも、ラベルの費用（記録と `Draw`）は上の表の範囲にある（固定しないと `Draw` は 39〜43 µs で、効率コアに乗った回を含む）。

## GPU

| 場面 | クロック | GPU（中央値 / p95） | 測れたフレーム |
| --- | --- | --- | --- |
| 100 個のラベルだけ | P8（210 MHz） | 31.7 / 32.7 µs | 1,152〜1,184 |
| 16 本の線（行 R2 の場面）＋ 100 個のラベル | P0（1,920〜1,965 MHz） | 615.4・622.5・622.5 / 628.7〜632.8 µs | 1,227〜1,231 |
| 16 本の線だけ | P0（1,920〜1,965 MHz） | 616.4・620.4・621.5 / 628.6〜634.8 µs | 1,222〜1,224 |

- ラベルだけのフレームは GPU の仕事が軽く、GPU は測っている間ずっと P8（210 MHz）にいた。31.7 µs は P8 の値である
- P0 の値を得るため、行 R2 の 16 本の M4 の線（1 本 7,680 点、太さ 1.5、シード `0x4879` の歩み）の下にラベルを描き、線だけのフレームとの差を取った。交互の 3 回の差は −1.0、+2.1、+1.0 µs で、回ごとの揺れ（線だけで 616.4〜621.5 µs）の中にある。P8 の 31.7 µs をクロックの比（210 / 1,935）で割り引くと約 3.4 µs で、差がこの揺れに埋もれることと合う
- 線だけ・線とラベルのどちらも、`Clear` を含む。`Clear` だけのフレームは 2 つのタイムスタンプが同じ値で 0.0 µs だった
- 1 フレーム 0.62 ms の線の場面を続けて描くと、クエリの輪（4 組）が埋まったフレームは測らない（設計書 §5.3）。1 回 20,030 フレームを描き、1,200 を超えるフレームを測った

## 新しい文字列

| 項目 | 値 |
| --- | --- |
| 新しい文字列の最初の整形（`TextEngine.Measure`、"1000000.00" から 7.31 刻みの 1,000 個、1 個ずつ測る） | 中央値 2.8〜2.9 µs、p95 5.3〜5.6 µs、最小 2.5〜2.7 µs |

- 最初の `Draw` の幅は、プロセスで最初の DirectWrite の呼び出しが、フォントのファイルを開いてキャッシュを作る時間を含むためと考えられる。2 回目からの新しい文字列は上の 2.8 µs で整形される
