# G11: 座標系の polar の計測

行 G11（Issue #149）の計測の記録。設計書 §4.4 の polar（theta = x）と cartesian で、1 フレームの時間を比べた。場面はロードマップの G11 の行のとおりで、要件 §5 の参照機で測った。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。測った後に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、ガイドなし（`ShowAxes`・`ShowGrid` が偽、`Padding` 0）。cartesian はパネルの全体で x に沿って 1,920 画素列。polar は R = 540、外周 L = ⌈2π · 540⌉ = 3,393 画素の角度の区切り |
| ワーカー | `PlotWorkerPool.Shared`（論理プロセッサの数 − 1）。プロセスの優先度は High、コアに固定しない |
| 1e9 点の線 | 行 S2 の場面: `samples/Shared/WalkFile.cs` の 1e9 点の `float` のメモリマップの列、X は `UniformColumn`。台本も S2 と同じ（全体から 100 万分の 1 まで 2^(1/8) 倍ずつ拡大し、2 倍ごとに 10 フレームのパン、全体へ戻る 531 フレーム）を 3 回、最初の 30 フレームを捨てた 1,563 フレーム。フレームごとに `ScaleX` の domain を台本の範囲にした仕様を描く。y の domain は学習 |
| 1e7 点の area と bar | 等間隔の X、シードつきの正弦波と雑音の `float` の Y。行 G4・G10 と同じく、毎フレーム新しい x の domain（データの 99〜100 % の 64 通り）。600 フレームのうち最初の 100 を捨てた 500 フレーム |
| 空の場面 | 層のない仕様（背景の `Clear` とパネルの矩形だけ）。GPU の固定分を見るため |
| 測る範囲 | CPU は `HeadlessRenderer.Render(PlotSpec)` の 1 回（コンパイル・M4・記録・`Clear`・`Draw`）。GPU はフレームのタイムスタンプのクエリ（`IGpuBackend.LastFrameTime`）。100 フレームごとに `ReadPixels` で GPU を待つ（測る範囲の外） |
| 回 | 線・area・bar・空の順に、それぞれ cartesian、polar を続けて 1 回ずつ。これを 3 回。線は別に、cartesian と polar を交互に 3 回、GPU の時間をフレームごとに時刻つきで記録した |
| GPU のクロック | `nvidia-smi --query-gpu=timestamp,clocks.gr,pstate` を 100〜200 ms ごとに記録した。area と bar と空の回は、どれも P0（1,665 MHz）だった（area の cartesian の 2 回で、最初の 1 標本だけ P8）。表の線の cartesian の回は、すべてのフレームが P0 だった。polar の線の回は、回の時間の 3〜4 割が P5 と P8 だった（下） |

1e9 点のファイルは、この表より前の回で書いて読んだもの。ピラミッドは各回の最初のフレーム（捨てるフレーム）で作った。

## 結果

中央値 / p95（µs）。各欄は 1 回目、2 回目、3 回目:

| 場面 | CPU（cartesian） | CPU（polar） | GPU（cartesian） | GPU（polar） |
| --- | --- | --- | --- | --- |
| 1e9 点の線 | 940 / 3,896、907 / 3,800、970 / 3,685 | 1,601 / 6,241、1,837 / 6,358、1,715 / 6,195 | 34 / 47、34 / 48、36 / 95 | 45 / 142、46 / 142、45 / 147（P0 のフレームだけ） |
| 1e7 点の area | 1,679 / 1,899、1,556 / 1,813、1,516 / 1,713 | 3,007 / 3,375、2,978 / 3,262、2,926 / 3,226 | 95 / 100、95 / 100、95 / 99 | 319 / 329、319 / 326、319 / 325 |
| 1e7 点の bar | 1,455 / 1,602、1,507 / 1,859、1,552 / 1,984 | 2,708 / 3,061、2,723 / 2,939、2,828 / 4,357 | 64 / 66、64 / 67、64 / 68 | 320 / 335、320 / 344、321 / 332 |
| 空 | 27 / 70、30 / 73、28 / 60 | 32 / 62、30 / 78、33 / 72 | 24 / 24（3 回とも） | 24 / 24（3 回とも） |

- **CPU は polar が 1.7〜2.0 倍**。M4 と画素列ごとの Geom は沿う向きの画素の数だけ働き（§4.4）、polar では 1,920 画素列が 3,393 の角度の区切りになる（比 1.77）。中央値の比は、線で 1.70・2.03・1.77、area で 1.79・1.91・1.93、bar で 1.86・1.81・1.82。1.77 を超える分の内訳は測っていない（polar の記録の段は、点ごとの sin と cos、台形から極座標の台形への写しと小片への切り分けを足す）
- **小片の数**: 線の小片（記録した線分）は 1 フレームに中央値 13,122、最大 13,562 で、cartesian の線分（中央値 7,505、最大 7,677）の 1.75 倍、つまり角度の区切りの数の比とほぼ同じ。M4 の線分は 1 片で済み（§4.4 の n ≤ 2 の上限には届かない）、拡大して点の少ない画面（スパン 1e4 点未満）では長い線分が分かれ、中央値 2,943、最大 9,895 だった（JIT で数えた。時間は測っていない）
- **`DrawSectors` の GPU 時間**: 空の場面は 24 µs で、area の polar の 319 µs から引くと、3,393 の小片の 1 回の呼び出し（3 つの段）が約 295 µs になる。cartesian の area の台形（1,920）は約 71 µs。bar の polar（3,779 の小片）も約 296 µs。極座標の台形は、細い楔ごとに、辺から √2 / 2 の内と外の帯（見積もりで約 2.4 画素幅）で 32 点を数える（§5.3）。点ごとの判定を共通のループと傾いた縁のループに分けるまでは、area の 1 フレームの GPU 時間が 1.96 ms だった（JIT のスクラッチで 1 回。§5.3）
- **GPU の線**: polar の線の回は、回の時間の 3〜4 割で GPU のクロックが P5・P8（315〜495 MHz）に下がった。フレームは CPU の時間が長く GPU の仕事が少ないので、GPU が休むためである。表の polar の GPU は、前後の時計の標本がどちらも P0 のフレーム（1,543・1,522・1,553 フレームのうち 1,023・960・1,125）だけで取った。すべてのフレームでは、中央値が 47、132、46 µs と回で開いた。P0 のフレームでも p95 は 142〜147 µs と中央値の 3 倍あり、cartesian の p95 も 47〜95 µs と回で開く。読み戻しを止めて 1,665 MHz のフレームだけに絞っても、polar の p95 は 134 µs、cartesian は 91 µs だった。フレームごとの GPU の時間と、そのフレームの線分の数の相関は 0.05（cartesian は 0.08）だった。polar の上位 5 % のフレームはスパン 1.4e4〜1.3e7 点（拡大の中ほど）にあり、線分の数が最も多い全体の画面（スパン 3e8 点以上）は中央値 49 µs、p95 53 µs だった。p95 は描く量でなく GPU の状態の幅なので、比は出さない。中央値は P0 で 34〜36 µs と 45〜46 µs で、線分の数の比（1.75）より小さい
- **転送**: 1 フレームに GPU へ送る記録は、線で polar 262 KB（線分 13,122 × 20 B、中央値）と cartesian 150 KB（7,505 × 20 B）、area で 163 KB（小片 3,393 × 48 B）と 92 KB（台形 1,920 × 48 B）、bar で 181 KB（小片 3,779 × 48 B）と 69 KB（矩形 約 2,153 × 32 B、パネルを含む）。どれも画素で抑えられ、データの量によらない（要件 R-1）。数は JIT で記録を数えた
- **確保**: 捨てたフレームの後、area・bar・空の回と polar の線の回はどれも 0 バイト。cartesian の線の 3 回のうち 2 回で、1 回の走りに 56 B が 1 度出た。行 G10 の記録の Issue #141（`M4Batch.Wait`）と同じで、main にもある。温まった後の polar の仕様の描き直しは 0 バイト（`CoordPolarTests.Polar_Warm_AllocatesNothing`、`SectorTests.Warm_AllocatesNothing`）

どちらも警告 0。`HelloPlot` と `SpecPlot`（ハードウェア、4 枚）の PNG は、main のものと画素まで同じだった（`cmp` でバイトまで一致）。増分のうち 21,312 B は極座標の台形の 5 つのシェーダのバイトコードで、32 点のループを展開した `SectorMaskPS` が 18,428 B を占める。`HelloPlot` の残りは、バックエンドの極座標の台形のパイプラインと `RenderList.DrawSectors` のコード、`SpecPlot` はそれに polar の仕様・変換・配置のコードが加わる。コードの分の内訳は測っていない。
