# I4a: 注釈の計測

行 I4a（Issue #386）の計測の記録。設計 §9 の「注釈（行 I4a）」の項のとおり、2 つの場面を測った。注釈のヒットテストは要件 P-5（p99 1 ms 以下）、注釈をドラッグするフレームは要件 P-1（1 フレームの p95 が 8 ms 以下）と比べる。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F（16 スレッド）、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。公開の API だけを使う。測った後にデータと一緒に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light`、タイトルあり |
| データ | 1e9 点の `float` の線（`samples/Shared/WalkFile.cs` のランダムウォーク、4 GB のメモリマップのファイル、ページキャッシュに載っている）。x は `UniformColumn` |
| ワーカー | `PlotWorkerPool.Shared`。プロセスの優先度は High |
| 慣らし | 索引ができるまでフレームを描き、整形のキャッシュを 8,192 個の別の文字列で満たす |
| ヒットテスト | ドラッグできる注釈 1,024 個（線・矩形・テキスト・マーカーを 256 個ずつ、シード 42 でパネルの割合に一様に置く）。シード 42 の 1,050 か所の画素で `PlotEngine.HitArea` の 1 回の CPU 時間を測り、最初の 50 回は数えない |
| ドラッグ | ドラッグできるマーカー 1 つ（x はデータの中央、y はパネルの割合 0.5）を、左ボタンで掴んで 330 フレーム動かす（横に正弦でパネルの幅の ±30 %、縦にその倍の速さでパネルの高さの ±20 %）。1 度流して慣らしてから、2 度目の 330 フレームのうち最初の 30 を除く 300 フレームを測る。CPU 時間は移動と `RenderFrame`、GPU 時間は `LastFrameTime`、確保は同じ範囲の `GC.GetAllocatedBytesForCurrentThread()` の差の和 |
| 回 | ヒットテストとドラッグを交互に 3 回ずつ（プロセスを 6 度） |

## 結果

| 回 | ヒットテスト p50 / p99 / 最大（ms） | ドラッグの CPU p50 / p95 / 最大（ms） | GPU p50 / p95 / 最大（ms、時間の届いたフレーム） | ドラッグの確保 |
| --- | --- | --- | --- | --- |
| 1 | 0.0119 / 0.0228 / 0.1364 | 0.281 / 0.435 / 0.564 | 0.235 / 0.243 / 0.630（287） | 0 B |
| 2 | 0.0122 / 0.0164 / 0.0227 | 0.294 / 0.443 / 0.720 | 0.236 / 0.244 / 0.651（290） | 0 B |
| 3 | 0.0118 / 0.0146 / 0.0340 | 0.260 / 0.333 / 0.752 | 0.233 / 0.236 / 0.240（285） | 0 B |

- **要件 P-5**: 1,024 個の注釈の上のヒットテストは、p99 0.023 ms 以下で、1 ms を大きく下回った。1,000 か所のうち 389 か所が注釈に当たった（同じ並びの位置なので 3 回とも同じ）。調べるのは最後の記録で写した形の並び（ドラッグできる注釈だけ）を後ろから 1 つずつで、注釈の数に比例する
- **要件 P-1**: ドラッグのフレームの p95 は、CPU 0.33〜0.44 ms、GPU 0.24 ms で、8 ms を大きく下回った
- **ドラッグが軽い理由**: ドラッグの間は毎フレーム全部を描き直す（設計 §5.4）が、注釈の変化は計画の「記録」の段だけを走らせ、配置も取り出しもしない（設計 §4.8 の「差分（行 I4a）」）。そのため、1e9 点の線の M4 の取り出しはし直さず、前のフレームの取り出しから記録し直すだけである。行 I1a のパン（ビューが毎フレーム変わり、取り出しをし直す）の CPU p95 1.1〜1.2 ms より軽い
- **確保**: ドラッグの 300 フレームで 0 B
