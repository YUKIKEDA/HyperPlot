# W1b3: ラスタのミップマップの待たない更新の計測

行 W1b3（Issue #318）の計測の記録。設計 §9 の「ラスタのミップマップ（行 W1b3）」の項のとおり、2 万 × 2 万の `float` のラスタを `PlotEngine` に置いた最初の構築と、列全体を `Invalidate` した後の更新を、main（更新を待つ）と比べた。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F（16 スレッド）、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリーと main f2a9642 の作業ツリー。常駐キャッシュの送る量を読むため、データの道のハーネスの名前を借りた。測った後にデータと一緒に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light`、タイトル「Raster」 |
| データ | 2 万 × 2 万の `float`（sin(x / 800) · cos(y / 600)）を生のファイルに書き、`Column.MapFile<float>` で読む。ページキャッシュに載っている |
| ワーカー | `PlotWorkerPool.Shared`（15 本）。プロセスの優先度は High。最初のフレームの揺れを見るために 4 本とも比べた |
| 慣らし | 同じタイトルの 300 × 300 のラスタを 10 フレーム描いてから、大きなラスタの仕様を置く |
| 最初の構築 | 仕様を置いてから、16.7 ms ごとにフレームを描き、暫定でないフレームが出るまで |
| 更新 | 続けて列全体を `Invalidate` し、同じく暫定でないフレームが出るまで |
| 測る範囲 | CPU は `SetPlot` と `RenderFrame` の 1 回（`Stopwatch`）。送る量は、バックエンドが送る前の常駐キャッシュのそのフレームの書き込み（`BytesThisFrame`。バックエンドを包んで読んだ） |
| 回 | main と PR を交互に 3 回ずつ（プロセスを 6 度） |

## 結果

時間は ms。フレームの欄は、最初のフレームの後の暫定のフレームの数と、その中央値 / p95 / 最大。

| | 回 | 最初の構築: 最初のフレーム | フレーム | 更新: 最初のフレーム | フレーム | 更新の間に送らなかったフレーム |
| --- | --- | --- | --- | --- | --- | --- |
| main | 1 | 510.8 | 2: 10.3 | 451.0 | 2: 1.1 | — |
| main | 2 | 515.1 | 2: 14.1 | 454.3 | 2: 1.4 | — |
| main | 3 | 500.2 | 2: 16.0 | 443.7 | 2: 1.7 | — |
| PR | 1 | 31.8 | 30: 0.71 / 12.5 / 13.0 | 0.63 | 29: 0.54 / 0.72 / 9.6 | 28 / 29 |
| PR | 2 | 0.88 | 32: 0.56 / 1.17 / 16.4 | 0.66 | 27: 0.52 / 0.82 / 12.1 | 26 / 27 |
| PR | 3 | 32.2 | 28: 0.59 / 1.08 / 9.7 | 0.48 | 27: 0.50 / 0.86 / 7.3 | 26 / 27 |

- **待たない**: main の最初のフレームは、ミップマップの段 1〜6 を作り終えるまで 0.50〜0.52 s 待ち、`Invalidate` の後のフレームも 0.44〜0.45 s 待つ。PR は待たずに戻り、作る間に 28〜32 フレーム、更新の間に 27〜29 フレームを描く。作り終える時刻（約 28〜32 × 16.7 ms）は main と同じ程度
- **更新の間は送らない**: 更新の間のフレームは、最後の 1 フレームを除いて送る量が 0 B だった（決定 2・3）。更新が終わったフレームで、変わった行のタイルを送り直す
- **最大の送る量**: どちらの回も最大は 6,922,656 B（26 面）で、1 フレームの予算（4 MB）を超える。`PlotEngine` は `HeadlessRenderer.Render` を通して描き、それが常駐キャッシュの `Unbounded` を立てるためである。main でも同じなので、この行の変更ではない。Issue #319 にした
- **最初のフレームの揺れ（0.8〜32 ms）**: `SetPlot` は 0.01 ms で、残りはその `RenderFrame` の中にある
  - ミップマップを作る（`MakePyramid`、段のメモリ約 533 MB を確保する）のは 0.02〜0.12 ms で、バックエンドの描画は 0.3〜0.8 ms だった
  - 最初のフレームで、15 本のワーカーが一度に平均を始める。15 本のまま 10 回走らせると、0.74〜17.1 ms に揺れた。4 本では 10 回とも 0.73〜1.36 ms だった
  - したがって、揺れは UI のスレッドがワーカーと CPU を取り合う分である。行 W1b1 の 2 度目の構築と同じで、ワーカーの優先度は Issue #293 で決める
- **作る間のフレームの p95 と最大**: 最大（7〜16 ms）の中には、作り終えて 26 面のタイルを書くフレームがある（送る量が 0 でない唯一のフレーム）。どのフレームが最大だったかは記録していない
