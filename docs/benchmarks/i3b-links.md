# I3b: リンクの計測

行 I3b（Issue #377）の計測の記録。設計 §9 の「リンク（行 I3b）」の項のとおり、2 つの場面を測った。ビューのリンクは要件 P-1（1 フレームの p95 が 8 ms 以下）、カーソルのリンクは要件 P-6（マウスだけのフレームの p95 が 2 ms 以下）と比べる。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F（16 スレッド）、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。公開の API だけを使う。測った後にデータと一緒に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light` |
| 図 | 4 つのプロットを 2 × 2 に並べた図（`Figure.Concat(2, ...)`）。各プロットにタイトルと、1e9 点の線が 1 本 |
| データ | y は `float` のメモリマップのファイル（`samples/Shared/WalkFile.cs` のランダムウォーク、プロットごとに別の 4 GB のファイル、ページキャッシュに載っている）。x は `UniformColumn`（0 から 1 刻み） |
| ワーカー | `PlotWorkerPool.Shared`。プロセスの優先度は High |
| 時刻 | 手で進める `TimeProvider`。イベントの前に 16.7 ms 進め、イベント 1 つに 1 フレームを描く |
| 慣らし | 索引ができるまでフレームを描き、整形のキャッシュを 8,192 個の別の文字列で満たす |
| ビューのリンク | 4 つを `AddPlot` で `View` のグループに入れる。プロット 0 に行 I1a の台本（真ん中でホイールを 60 目盛り、ズームのアニメーション 150 ms、続けて左ボタンで 300 回動かすパン）。台本を 1 度流し、`ResetAll` で戻してから、2 度目の 362 フレームを測る |
| カーソルのリンク | 4 つを `Cursor` のグループに入れる。既定のホバー（`HitMode.X`、縦のクロスヘア、印、ツールチップ）で、プロット 0 の上を行 I2b の台本（左から右へ、上下に正弦で 330 フレーム）で動かす。台本を 1 度流してから（ツールチップの文字列を整形のキャッシュに入れる）、続く 300 フレームを測る。比べるために、リンクのない同じ場面も 1 回流した |
| 内訳 | カーソルの各フレームの後に、3 つのメンバーそれぞれで、ポインタの x の画素での `HitTest`（`HitMode.X`、半径 0）の時間を、フレームとは別に測った |
| 測る範囲 | CPU は入力と `RenderFrame`、GPU はフレームのタイムスタンプのクエリ（`LastFrameTime`）、確保は同じ範囲の `GC.GetAllocatedBytesForCurrentThread()` の差の和 |
| 回 | ビューとカーソルを交互に 3 回ずつ（プロセスを 6 度） |

## 結果

フレームは中央値 / p95 / 最大（ms）。

| 場面 | 回 | CPU | GPU（時間の届いたフレーム） | 確保 |
| --- | --- | --- | --- | --- |
| ビュー | 1 | 1.354 / 2.900 / 6.497 | 0.389 / 0.780 / 1.617（360） | 0 B |
| ビュー | 2 | 0.927 / 2.399 / 4.956 | 0.722 / 0.786 / 1.397（338） | 56 B |
| ビュー | 3 | 0.921 / 2.302 / 5.730 | 0.723 / 0.783 / 1.431（340） | 112 B |
| カーソル | 1 | 0.195 / 0.224 / 0.824 | 0.189 / 0.191 / 0.194（21） | 0 B |
| カーソル | 2 | 0.195 / 0.207 / 0.799 | 0.189 / 0.203 / 0.203（17） | 0 B |
| カーソル | 3 | 0.196 / 0.217 / 0.803 | 0.189 / 0.193 / 0.193（19） | 0 B |
| カーソル、リンクなし | 1 | 0.095 / 0.105 / 0.697 | 0.089 / 0.096 / 0.099（21） | 0 B |

メンバーごとの `HitTest`（900 回、ms）: p50 0.0005〜0.0007、p95 0.0014〜0.0021、p99 0.0027〜0.0035、最大 0.0049〜0.0250。

- **要件 P-1**: ビューのリンクのフレームの p95 は、CPU 2.3〜2.9 ms、GPU 0.79 ms で、8 ms を下回った。拡大の後、4 つのプロットの x はどれもプロット 0 と同じ値（幅 17,747 点）だった
- **ビューの重さ**: 行 I1a の 1 プロットの台本（CPU p95 3.8〜4.4 ms、`docs/benchmarks/i1a-interaction.md`）より軽い。2 × 2 の図では各パネルの幅が半分なので、M4 の取り出しの画素列も半分になる。4 つのプロットの取り出しは、同じワーカーの 1 つのパスで並んで走る（行 G6c の図と同じ）
- **要件 P-6**: カーソルのリンクのフレームの p95 は、CPU 0.21〜0.22 ms、GPU 0.19〜0.20 ms で、2 ms を下回った
- **カーソルの重さ**: リンクのない同じ場面より、CPU と GPU のどちらも約 0.1 ms 長い。3 つのメンバーのクロスヘアと印を、毎フレーム描く層に足す分である。メンバーの `HitTest` は p99 で 0.0035 ms 以下で、その内訳は小さい
- **確保**: カーソルは 0 B。ビューの 56 B は、行 I1a の記録と同じく、NativeAOT が `Lock` を初めて待つときの初期化の確保（不変条件 3 の除外）で、1 回の実行に 0〜2 回出た
- **GPU 時間の届いたフレーム**: カーソルは 300 のうち 17〜21 で少ない。時間は数フレーム後に届き、クエリの組が空いていないフレームは時間を持たない（設計 §5.2）。ビューは毎フレーム描き直すので、ほとんどのフレームに届いた

## 計測で見つけたこと

- 最初のカーソルの計測は、台本を 1 度だけ流して測ったので、毎フレーム 624 B を確保した。リンクのない場面でも同じ量で、初めて出るツールチップの文字列を、満ちた整形のキャッシュに入れる分である。行 I2b の記録と同じく、台本を 1 度流してから測った（上の表）
- ポインタをパネルに置いたままホイールで拡大と縮小を繰り返すと、温まった後もフレームが確保する。main でも同じ量で、リンクとは関わらないので、Issue #378 に記録した。この PR のテスト（`LinkTests.LinkedFrames_AllocateNothing`）は、ポインタをパネルから外してからホイールを測る
