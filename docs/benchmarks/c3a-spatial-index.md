# C3a: 空間タイル索引の計測

行 C3a（Issue #405）の計測の記録。設計書 §9 の「空間タイル索引」の場面を、要件 §5 の参照機で測った。main に索引はないので、比べる相手は要件の値（P-5・P-8）と設計書 §3.4 の計算である。要件 P-15 の値と `Dispose` の待ちは、この記録から `docs/adr/0001-spatial-index-build-time.md` で決めた。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Intel Core i5-13400F（P コア 6・E コア 4、16 スレッド）、48 GB、WD Blue SN580 1TB、Windows 11。データのファイルは D:、写しの一時ファイルは C: の `Path.GetTempPath()` |
| ビルド | `HyperPlot.DataPath` の NativeAOT Release（win-x64、周回は 2,025,984 B、`touch` の場面を足した後は 2,032,640 B、発行の警告 0）、.NET 10.0.14。プロセスの優先度は高。ワーカーはコアに固定しない（設計書 §9） |
| コミット | 周回は `26ac88c`。「`RowsPerUnit`」と「写しを閉じる時間」の節は `6ed9164`（その後の変更は、既定の `RowsPerUnit`、書き込みの単位が 256 行ごとに構築の停止を確かめること、Linux の確保の手順） |
| データ | 1e9 点の `float` の x と y（各 4,000,000,000 B、メモリマップ）。シード `0x4879706572506C6F`（10 進で 5222328823924681839）。変換なし、範囲は索引が求める |
| ワーカー | 8 本（自分のプール）と、`Shared` の既定の数（15 本） |
| 回 | 2 つの分布 × ワーカー 2 通りを、順序を入れ替えて 3 周。1 つのプロセスが、ファイルを書き直して（ページキャッシュに載っていない）1 回、続けて（載っている）1 回、索引を作る |
| 機械の状態 | `watch-machine.ps1` が 5 秒ごとに、CPU の性能、空きメモリ、場面とほかのプロセスが使った CPU 時間を書く。周回の間、同じ機械でほかのプロジェクトのビルドと試験が走っていた（下の「ほかのプロセスの影響」） |

データは `PointFiles.Write` が作る。1,048,576 点のブロックごとに、シードとブロックの番号から xorshift64* の状態を作るので、同じシードは同じバイトになる。

- **一様**: x と y が [0, 1e6) の一様な乱数
- **塊**: 32 個の正規分布の塊と外れ値。塊の中心は [0, 1e6)² の一様な乱数、標準偏差は 10 × 3000^u（u は [0, 1) の一様な乱数、10〜30,000）、塊 k の重みは 1 / (k + 1)。点の 0.1 % は、(−1e9, 1e9)² の一様な外れ値である。範囲が 2e9 に広がるので、塊は深い水準まで分かれる

2 回書いた SHA-256 は、どちらの分布も 2 回とも同じだった。

| 分布 | x | y |
| --- | --- | --- |
| 一様 | `B230DF4489A9357F1DAE15095EBCD5E42D6C12BD716F29A9BD791D45404A66CF` | `7D55E719E906920946F63AF5905E7AC8F34000675AC8D0ABFFD7E0CDA5AA2A26` |
| 塊 | `C997C27565BF1F122A426DC8FDF2648FD92C6BEE964B86839DC122AC3FC0B635` | `3DF970DA51A5918CFC381FAC1DDD97553B0C1E5EDB23D63A7B9543CA872F73CB` |

## 構築の時間

`BuildSpatialIndex` から `Completion` まで（秒）。各欄は 1 周目、2 周目、3 周目。

| 分布 | ワーカー | ファイルが載っていない | 載っている |
| --- | --- | --- | --- |
| 一様 | 8 | 58.2、58.3、53.2 | 48.1、53.8、53.3 |
| 一様 | 15 | 49.8、51.3、57.3 | 44.6、50.3、55.4 |
| 塊 | 8 | 137.6、142.3、136.3 | 138.7、144.2、122.6 |
| 塊 | 15 | 134.6、134.7、126.6 | 131.6、140.5、126.5 |

- **要件 P-15**: ワーカー 8 本で、一様は 48.1〜58.3 秒、塊は 122.6〜144.2 秒。値は一様 75 秒、塊 180 秒とした（ADR 0001）
- **ワーカーの数**: 8 本と 15 本の差は、どちらの分布でも周ごとの揺れの中にある。1 つの索引を同時に進めるワーカーは 8 つまで（`GroupCount`）で、9 本目からは別の仕事のためのワーカーである
- **ページキャッシュ**: 載っていないファイルでは、範囲の段が 3〜4 秒長い。ほかの段は、範囲の段がファイルを読み終えているので変わらない

段ごとの時間（秒）。24 回の最小〜最大。

| 段 | 一様 | 塊 |
| --- | --- | --- |
| 確保 | 0.0027〜0.0045 | 0.0026〜0.0045 |
| 範囲（載っていない / 載っている） | 3.27〜4.78 / 0.76〜0.88 | 3.88〜4.55 / 0.74〜0.82 |
| 1 回目の数え上げ | 2.61〜4.13 | 2.10〜3.12 |
| 粗いスナップショットの公開まで（載っていない / 載っている） | 6.21〜8.29 / 3.37〜5.01 | 6.03〜7.34 / 2.87〜3.38 |
| 数え上げの走査 | 1 回、7.2〜11.7 | 8 回、合わせて 58.9〜72.7（1 回 2.6〜15.8） |
| 表 | 0.016〜0.031 | 0.031〜0.035 |
| 書き込み | 33.8〜44.7 | 59.6〜69.3 |

- 粗いスナップショットは、どの回も 8.3 秒以内に公開された（P-15 の「10 秒以内」）
- 書き込みは、一様で全体の 7 割前後、塊で 4〜5 割を占める。書き込みの時間は、ワーカーが 8 本でも 15 本でも変わらない
- 塊の分布は、最も深い水準が 32 で、8 回の走査になる。一様は水準 9 で、1 回で終わる

### ほかのプロセスの影響

周回の間、同じ機械でほかのプロジェクトのビルドと試験（`XylemUI.*.Tests`、`ElasticLM.*.Tests`、`VBCSCompiler`）が走っていた。構築の間にほかのプロセスが使った CPU 時間を、構築の時間で割ってコアの数にした。塊の 12 回は、この数と一緒に動いた。

| ほかのプロセス | 塊の構築（8 本と 15 本） |
| --- | --- |
| 0.6〜0.7 コア（3 回） | 122.6、126.5、126.6 秒 |
| 2.3〜3.9 コア（9 回） | 131.6〜144.2 秒 |

- 一様の 12 回は、ほかのプロセスが 0.7〜1.7 コアの 4 回で 44.6〜58.2 秒、2.0〜5.6 コアの 8 回で 50.3〜58.3 秒だった。載っていないファイルの回が混ざるので、塊ほどはっきり分かれない
- 数え上げの走査（ディスクを使わない）も動いた。一様の 1 回の走査は、ほかが 4.4 コア以上の 5 回で 9.6〜11.7 秒、1.7 コア以下の 4 回で 7.2〜9.1 秒だった
- 構築の間の空きメモリは、最小で 3.9 GB だった。CPU の性能のカウンタ（定格の周波数に対する割合）は、140〜161 % だった
- この前に `6ed9164` で測った 3 周は、機械の状態を書いていなかった。一様の 8 本で 50.2〜77.3 秒、塊の 8 本で 131.2〜158.7 秒で、遅い回は時間帯で固まっていた。その 3 周の値は、この記録の表に使っていない

## `Dispose` の待ち

`Dispose` を呼んでから戻るまでの時間。周回のそれぞれの構築の後に、同じデータで構築を始め直して測った（24 個のプロセス、時点ごとに 1 回）。

| 時点 | `Dispose` | そのとき処理中だった仕事のいちばん長いもの |
| --- | --- | --- |
| 構築を始めた直後 | 0.01〜6.1 ms | 0〜4.4 ms |
| 数え上げの途中 | 1.3〜4.6 ms | 0〜50 ms |
| 書き込みを始めた直後 | 1.1〜3.8 ms | 0〜57 ms |

書き込みを始めた直後は、3 つの修正の前後で次のように変わった。

| コミット | `Dispose` | 内訳 |
| --- | --- | --- |
| `3197e0f`（修正の前） | 25〜44 秒 | 処理中の単位を待つのは 8〜27 ms。残りのほとんどは、ビューを外すとき（ページの書き出しを含む）で、ファイルを閉じるのに 1.2〜1.8 秒 |
| `f7e3182`（書き出さずに外す） | 1.3〜2.9 秒 | ビューを外す 0.56〜1.1 秒、閉じる 0.55〜0.9 秒 |
| `6ed9164`（閉じるのをスレッドプールに渡す） | 0.9〜3.7 ms。40 回のうち 1 回は 1,399 ms | 1,399 ms の回は、書き込みの最初の単位（1,396 ms）の終わりを待った |
| `26ac88c`（待つ前に構築を止め、書き込みの単位が 256 行ごとに確かめる） | 1.1〜3.8 ms（24 回） | 1 秒を超える回はなかった |

- `.NET` の `MemoryMappedViewAccessor.Dispose` は、書き込めるビューが開いていると、変えたページをファイルに書き出して待つ（dotnet/runtime v10.0.0。Windows は `FlushViewOfFile`）。消すファイルなので、ビューのハンドルを先に閉じて書き出さない
- 書き込みを 200 単位進めてから `Dispose` を呼ぶと（`6ed9164`、`RowsPerUnit` は 65,536、8 回 × 分布 2 つ × ワーカー 2 通り）、`Dispose` は 12〜71 ms で戻り、写しを閉じる仕事はスレッドプールで 1.0〜3.6 秒かかった。`Dispose` はこの時間を待たない

### 書き込みの最初の単位

書き込みの段では、グループごとの最初の単位（8 つ）だけが長い。

| `RowsPerUnit` | 最初の 8 単位の平均 | そのほかの単位の p99 |
| --- | --- | --- |
| 16,384（`26ac88c`、一様） | 0.56〜1.70 秒 | 6.6〜8.2 ms |
| 16,384（`26ac88c`、塊） | 0.62〜0.69 秒 | 10.6〜13.2 ms |
| 65,536（`6ed9164`、一様） | 1.07〜3.30 秒 | 25〜39 ms |

長いのは、写しのページに初めて書くときである。`touch` の場面で確かめた。12 GB の写しを作り、8 本のスレッドが、まだ誰も書いていないページに 1 つずつ値を書く（1 本 12,288 ページ、x の領域の乱数の位置）。これを 8 回続け、最後に 1 回目と同じページにもう一度書く。3 つのプロセスの値を並べる。

| 回 | 8 本が 12,288 ページずつ書く時間 | 1 ページあたり |
| --- | --- | --- |
| 1 回目（新しいページ） | 598 ms、192 ms、199 ms | 16〜49 µs |
| 2 回目（新しいページ） | 119 ms、67 ms、65 ms | 5.3〜9.7 µs |
| 3〜8 回目（新しいページ） | 33〜46 ms | 2.7〜3.8 µs |
| 書いたことのあるページ | 0.7〜1.0 ms | 0.06〜0.08 µs |

- 新しいページへの書き込みは、書いたことのあるページの 40 倍以上かかり、写しを作った直後の 10 万〜20 万ページはさらにその 2〜16 倍かかる。写像して最初の 1 回の書き込みそのものは 0.03 ms である
- 書き込みの段の最初の単位は、16,384 行を別々の葉に書く。葉のうちそのグループの分は 1 ページより小さい（一様で 1 つの葉は 3,815 点、3 つの領域で各 15 KB）ので、1 行ごとに 3 つの領域の新しいページに書く。最大 49,152 ページで、上の 1 回目の速さ（16〜49 µs）なら 0.8〜2.4 秒になる。測った 0.56〜1.70 秒と同じ大きさである
- `Dispose` は、この単位の終わりを待たない（上の表の `26ac88c`）

- 9p は `fallocate` を持たず、glibc の `posix_fallocate` がブロックごとに 1 バイトを書く。12 GB で 17.4 分は 1 MB あたり 87 ms で、1 MB ずつに分けた後と同じ速さである
- 確保は 1 つの仕事で、分ける前は `Dispose` がその終わりまで待った。分けた後は、1 MB ごとに構築の停止を確かめる（ADR 0001）
- Windows の確保は 2.5〜4.5 ms である（上の「仕事の長さ」）

## 負荷の下で見つかった 2 つの競合

`6ed9164` の前に、1e9 点の計測と並べて試験を走らせたとき、2 つの失敗が出た。どちらも直した。

- **完了の順**: `Completion` の `Task` が、確定の公開の仕事が `JobEnded` に届く前に終わっていた。待った側が仕事の記録を読むと、最後の 1 つが欠けることがあった。`Task` は `JobEnded` の後に終わるようにした
- **グループの位置**: 構築は、行を単位に切り分ける前から見えていた。空いたワーカーが切り分けの途中のグループから単位を取ると、作業用の領域がまだなく、`ArgumentOutOfRangeException` になった。グループは「取れる単位なし」で始める。この競合を必ず起こす試験は書けていない。空いた 8 本のワーカーが 1 つの構築を競う試験が、負荷の下でまれに捕まえる

## 1e8 点での数え上げの変更

`51ac8c7` は、数え上げの走査で、下に分けているセルのない分けたセルに印を付け、点がそこで降りるのをやめるようにした。1e8 点の塊の分布の構築は、13.2〜13.4 秒から 9.5〜9.9 秒になった。表は変わらない。
