# G5a: Position の計測

行 G5a（Issue #208）の計測の記録。設計書 §5.5.3 の Position の道（カテゴリの x の積み上げのセルの和、数の x の積み上げの累積の列、並べ）を、ホストと同じ形（`HeadlessRenderer`、ハードウェアの D3D11）で測り、要件 P-1（CPU と GPU がそれぞれ p95 で 8 ms 以下）と P-2（索引の構築は 1 GB/s 以上）と比べた。要件 §5 の参照機で測った。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。公開の口だけを使う。測った後に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light`（軸・グリッド・色の凡例つき） |
| ワーカー | `PlotWorkerPool.Shared`（15 スレッド）。プロセスの優先度は High、コアに固定しない |
| カテゴリの x のデータ | 1e8 行。x のカテゴリは (i · 2654435761) mod nx、色のカテゴリは ((i + 7) · 2654435761) mod 8 の 8 群、Y・YMin・YMax は `float` の `Column.Wrap`（シード 5） |
| 数の x のデータ | 1e8 行を x の順に、8 群を 1 行ずつ交互に並べる（どの群も区間に並ばず、集める道）。そろう場合は群が同じ x（行 i の x は ⌊i / 8⌋、x の和集合は 1.25e7 点）、ずれる場合は群ごとに 1/16 ずつずらす（和集合は 1e8 点）。Y は `float`、X は `double` |
| 場面 | **積み上げた bar**: カテゴリの x、`ColorBy` で 8 群、既定の積み上げ。nx = 50 と 1e5。**積み上げた area**: 数の x、`FillBy` で 8 群、既定の積み上げ。**並べた bar と errorbar**: nx = 50、`Dodge(0.1)`。**比べる場面**: 数の x の area を `Position.Identity` で（行 G7c の分けた area） |
| 測る範囲 | **最初の描画**: 新しい計画で最初の `Render`（ワーカーの仕事と 1 フレーム）と、そのときのプロセスのメモリの増え。**作り直し**: Y を `Invalidate` した直後の `Render` を 5 回（中央値）。**フレーム**: 2 秒描いて温めた後の 300 フレーム。bar の場面は y の domain を毎フレーム変え（64 通り、記録をやり直す）、area の場面は x の domain を毎フレーム幅のまま 1/128 ずつずらす（64 通り、M4 を引き直す）。CPU は `Render` の 1 回、GPU はフレームのタイムスタンプのクエリ、確保は `GC.GetAllocatedBytesForCurrentThread()` の差 |
| 回 | 場面の順に 1 回ずつを 3 回 |

## 結果

ワーカーの仕事はミリ秒、フレームは中央値 / p95（µs）。各欄は 1 回目、2 回目、3 回目。

### ワーカーの仕事

| 場面 | 最初の描画 | 作り直し（中央値） | メモリの増え |
| --- | --- | --- | --- |
| 積み上げた bar（nx 50） | 102、95、123 | 102、81、97 | 85 MB |
| 積み上げた bar（nx 1e5） | 554、656、750 | 539、564、686 | 197 MB |
| 積み上げた area（そろう） | 2,371、2,134、2,438 | 1,361、1,288、1,468 | 1,015 MB |
| 積み上げた area（ずれる） | 6,399、5,815、6,220 | 5,972、5,740、5,915 | 7,250 MB |
| 並べた bar と errorbar | 652、627、590 | 205、197、213 | 1,167 MB |
| 比べる場面（分けた area） | 281、294、279 | 212、215、203 | 1,191 MB |

### フレーム

| 場面 | CPU | GPU | 確保（300 フレーム） |
| --- | --- | --- | --- |
| 積み上げた bar（nx 50） | 472 / 541、224 / 278、465 / 572 | 220 / 222、219 / 221、221 / 224 | 0、0、0 B |
| 積み上げた bar（nx 1e5） | 3,715 / 5,211、3,632 / 3,908、4,700 / 6,321 | 892 / 1,657、1,123 / 1,159、1,169 / 2,315 | 0、0、0 B |
| 積み上げた area（そろう） | 12,677 / 14,763、8,075 / 11,956、11,086 / 14,741 | 2,228 / 2,720、2,222 / 2,621、2,216 / 3,982 | 0、0、0 B |
| 積み上げた area（ずれる） | 14,208 / 18,883、12,095 / 17,014、10,342 / 14,696 | 2,211 / 2,628、2,219 / 4,736、2,221 / 4,206 | 0、0、56 B |
| 並べた bar と errorbar | 287 / 480、264 / 394、262 / 375 | 217 / 218、217 / 219、216 / 218 | 0、0、0 B |
| 比べる場面（分けた area） | 6,817 / 8,730、8,479 / 9,630、6,687 / 8,582 | 1,814 / 3,985、1,888 / 3,581、1,730 / 3,707 | 0、0、56 B |

- **カテゴリの x の積み上げ**: セルの和は 1e8 行で約 0.1 s（nx 50）と約 0.6 s（nx 1e5）。行を読む量は 1e8 × (4 + 4 + 4) B = 1.2 GB で、nx 50 は約 12 GB/s、nx 1e5 は約 2 GB/s（セルが L2 に収まらず、和の配列への書き込みが散らばる）。1 フレームはどちらも P-1 に収まる
- **画素より多いカテゴリ**: nx 1e5 で band は 1 画素未満で、画素列ごとに並びのピラミッドを引く。最初の実装は群ごとに 2 回（群の上端と次の群の下端）引き、1 フレームの CPU が 5.7〜7.9 ms / 6.3〜10.0 ms（p95 が P-1 を超えた）だった。隣り合う群は並びを共有するので、並びごとに 1 回引いて最小と最大を一緒に持つ形にし、上の表の値になった（§5.5.3）
- **数の x の積み上げ**: 累積の列を作る仕事は、そろう場合で約 1.3〜2.4 s（読む量 1e8 × 12 B = 1.2 GB で約 0.5〜0.9 GB/s。最初の描画には集める仕事も入る）、ずれる場合で約 6 s（和集合が 1e8 点で、8 群の P の列 8 本と X に 1e8 × (8 + 8 × 8) B = 7.2 GB を書く。メモリの増えはこの量）。最初の実装は 1 本のスレッドで行ごとに仮想呼び出しで読み、そろう場合 11〜15 s、ずれる場合 65〜76 s だった。x の範囲を区切ってワーカーで並列にし、行を 4,096 行の窓でまとめて読む形にして、上の値になった（§5.5.3）。要件 P-2（1 GB/s）は時系列のピラミッドの要件だが、同じ種類の前処理として比べると、そろう場合はその近く、ずれる場合は書く量が読む量の 6 倍で、それより遅い
- **積み上げた area の 1 フレーム**: 中央値で 8〜14 ms と、比べる場面（分けた area、6.7〜8.5 ms）の 1.2〜1.8 倍で、p95 は P-1 の 8 ms を超える。積み上げた群は band（YMin と YMax の 2 本の M4 と 2 つの包絡）で描き、area（1 本）より画素列の仕事が多い。隣り合う群が共有する累積の列の M4 を 1 回にまとめる形を試したが、CPU は変わらず（そろう場合 8.0 ms と 8.2 ms）、引き出しでなく写しと包絡と記録が重いので戻した。比べる場面も p95 が 8.6〜9.6 ms で P-1 を超えており、行 G7c の記録（`docs/benchmarks/g7c-color.md`: 系列 1 本あたり約 0.17 ms 増える）と同じく、P-1 は 1 系列の要件で、8 群の area はその外にある（群の数ごとの値は下の「群の数と P-1」。積み上げた area は 4 群まで収まる）
- **並べ**: 置く場所を変えるだけで、1 フレームは積み上げない分けた bar と同じ桁（0.3 ms）。最初の描画の約 0.6 s は、混ざる 8 群を集める仕事（行 G7c の集める道）と、群ごとのカテゴリの最小・最大（行 G7b）
- **確保**: 温まった後の 300 フレームで 0 B。ただし area の場面で、3 回のうち 1 回、1 フレームだけ 56 B を確保した。2,000 フレームを 3 回走らせても、1 つのプロセスで 1 回（1,578 フレーム目）だけで、積み上げない分けた area（行 G7c の道）でも出る。どの呼び出しかは確かめていないので、Issue #210 で調べる
- **GPU**: bar の場面は約 0.22 ms（nx 1e5 は画素列ごとの矩形で約 1 ms）。area の場面は約 2.2 ms で、p95 は 2.6〜4.7 ms

## 群の数と P-1（PR #211 のレビュー）

積み上げた area の 1 フレームが P-1 を超えるのが群の数によることを確かめるため、1e8 行を 1・2・4・8 群に分けて（行 i の群は i mod n、x は ⌊i / n⌋ で群がそろう）、積み上げた area（1 群は分けない層に `Position.Stack`）と積まない分けた area（`Position.Identity`）を、上の条件で測った。CPU の中央値 / p95（µs）。各欄は 1 回目、2 回目、3 回目。

| 群 | 積み上げた area | 積まない分けた area |
| --- | --- | --- |
| 1 | 4,216 / 5,475、4,029 / 5,300、3,983 / 5,604 | 4,025 / 4,982、3,875 / 5,359、3,966 / 5,597 |
| 2 | 4,190 / 5,819、4,833 / 5,810、4,190 / 6,129 | 3,746 / 4,196、4,391 / 5,287、3,812 / 5,311 |
| 4 | 5,818 / 7,245、7,216 / 7,756、6,112 / 7,857 | 5,017 / 6,034、5,050 / 6,642、4,518 / 6,001 |
| 8 | 10,197 / 13,791、9,830 / 14,217、9,495 / 12,866 | 8,047 / 8,684、6,491 / 8,640、7,613 / 9,160 |

- 1 群の積み上げは積まない area と同じ（約 4 ms）で、積み上げの道そのものは P-1 に収まる
- 積み上げた area は 4 群まで p95 が 8 ms 以下（7.2〜7.9 ms）で、8 群で超える。積まない分けた area は 8 群で p95 が 8.6〜9.2 ms と、こちらも超える。P-1 を超えさせているのは群の数（群ごとの M4 と記録）で、行 G7c の記録と同じく、P-1 は 1 系列の要件である
- GPU はどの群の数でも中央値 1.5 ms 以下
