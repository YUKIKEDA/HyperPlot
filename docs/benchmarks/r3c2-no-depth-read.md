# R3c2: 強調のない run の深度を読まないピクセルシェーダーの計測

行 R3c2（Issue #617）の計測の記録。常駐の印のピクセルシェーダーを 2 つにし、強調のない run（`Highlight` が 0）を深度（`SV_Position.z`）を読まないシェーダーで描くようにした（設計 §6.4 の「強調のない run の描き方」）。直す前と後を、同じ場所で交互に NativeAOT で測った（Issue #617 の決定 3）。

## 結果

- **選択のない場面は、どれも GPU 時間が減った**。組ごとの p50 の差（後 − 前）の平均は、1 部分で −0.96 ms（−0.82〜−1.15）、8 部分で −1.17 ms、64 部分で −0.56 ms、6 つの形の一様で −1.46 ms、中央の塊で −0.80 ms だった。6 組のどの組でも、後のほうが短い
- **1 部分の全体表示は、Issue #592 の読みを外した版と同じ幅になった**。後の p50 は 10.76〜11.15 ms（平均 10.95 ms）で、#592 の「試作のシェーダー」の版の 10.68〜11.59 ms（組ごとの平均 10.90〜11.04 ms）と重なる
- **選択のある場面は、前と同じ時間である**。矩形と投げ縄の全体表示の p50 の差は、組ごとに −0.11〜+0.13 ms、平均 0.00 ms と +0.02 ms で、どちらの側も幅は同じ（11.73〜12.45 ms と 11.83〜12.34 ms）。フレームの CPU 時間の p95 も同じ幅だった（矩形 0.68〜0.96 ms と 0.65〜0.91 ms、投げ縄 1.66〜2.40 ms と 1.72〜2.35 ms）
- どの回も、台本の 2 周目の 300 フレームの確保は 0 B で、失敗した回と時間の上限を超えた回はない
- 値は、ほかのプロセスが 1.81〜14.20 コアを使っている機械でのものである（回ごとの値は生の出力にある）

- 選択のある場面の後の側は、どの run も強調のあるシェーダーで描くので、描き方は前と同じである。差が組ごとに ±0.13 ms の中に収まるのはそのためで、run ごとのシェーダーの選びと、パネルごとに多くて 1 回の切り替えは、測れる費用にならなかった
- 選択のない場面の減りは、場面によって 0.56〜1.46 ms と違う。差を作るのは深度の読みだけで（fxc の `/O3` の出力で、深度を読まないシェーダーは入力が `v0.xy`、68 命令、読むシェーダーは `v0.xyz`、69 命令。頂点シェーダーは同じ）、GPU の中で、なぜこの読みの費用が場面で違うのかは分けていない（Issue #592 の Result と同じ）。直すものはないので追わない（オーナーの決定、2026-11-27、Issue #621）
- 1 部分の選択のない場面の前の側（11.66〜12.25 ms）と、選択のある場面の両側（11.73〜12.45 ms）は同じ幅である。選択の判定（頂点シェーダーの `Holds`）と範囲の塗りは、前の側の深度の読みに比べて測れる大きさではない

## 再現

```powershell
# 前（-Base のコミット）と後（チェックアウト）を発行し、6 組を交互に流す。機械の記録と GPU のクロックの記録を含む
pwsh -NoProfile -File benchmarks/HyperPlot.E2E/run-r3c2-no-depth-read.ps1 <出力ファイル> -Base bd46e42 -Rounds 6
# 1 つの場面（最後の 2 つの引数は、1 フレーム 1 行のファイルと選択）
HyperPlot.E2E.exe points 10000000 6 0.6 uniform 600 0 whole color Circle blocks draw frames.csv rectangle
```

スクリプトは、前のワークツリーを `.dev/r3c2-base` に、2 つの発行を `.dev/r3c2-pub-base` と `.dev/r3c2-pub-head` に置き、終わりに消す。選択の引数は `none`（既定）、`rectangle`、`lasso` である。生の出力は `.dev/out/r3c2-measure/`（1 回の試しは `.dev/out/r3c2-pilot/`）にあり、リポジトリには入れていない。
