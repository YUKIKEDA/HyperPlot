# R3b2: 重なりと予算の計測

行 R3b2 の計測の記録。設計書 §9 の「重なりと予算（行 R3b2、Issue #472）」の場面を、要件 §5 の参照機で測る。行 R3b2 の実装は 7 本の PR に分かれていて（Issue #472 の 2026-11-21 の決定）、この記録は 1 本目（Issue #577、ブロックと見えるブロック）の分である。後の本の計測は、その本の PR がこの記録に足す。

## 1 本目の結果（Issue #577）

- **道は 1 つのままでよい**: 1e7 点・8 部分の全体表示は、ページを丸ごと描く形でも見えるブロックだけを描く形でも、記録が同じである（1 フレーム 160 回の描画、1e7 点）。GPU 時間の p50 は、丸ごとが 10.63〜11.15 ms、見えるブロックが 10.70〜11.09 ms で、続けて測った 2 回の比（見えるブロック ÷ 丸ごと）は 0.98〜1.01 だった（6 組）
- **64 部分の拡大は要件 P-4 に入る**: CPU 時間と GPU 時間の p95 の和は 10.19〜10.80 ms（3 回）。描画は 1 フレームに平均 202.9 回、最大 384 回で、設計が挙げた最悪の約 9,800 回にはならなかった
- **要件 P-4**: 測った 8 つの場面は、どの回も 16.7 ms 以下である（10.19〜15.31 ms）。行 R3a と R3f の記録で超えていた 8 部分の全体表示（17.5〜17.6 ms）は 11.65〜12.79 ms、6 つの形に分けた層（GPU の p50 だけで 17.3〜18.0 ms）は 12.47〜12.72 ms になった
- **縁の外のセル**（PR #582 のレビュー、Issue #583）: ビューを印の届く幅だけ広げてセルを選ぶようにしたので、拡大の台本で描く点は、1 部分で 0.51 %、8 部分で 0.28 %、64 部分で 0.24 % 増えた（下の「縁の外のセルを描く分」）
- **確保**: どの回も、台本の 2 周目の 300 フレームは 0 B。1 周目の確保は、全部が計画の記録のうち層の記録の外（配置、目盛り、凡例）にある
- 値は、ほかのプロセスが 0.7〜2.5 コア（道の組）、0.76〜1.63 コア（それ以外の組）を使っている機械でのものである（回ごとの値は表にある）

## 時間の取れないフレーム（8 部分の全体表示）

上の表の 8 部分の回は、GPU 時間が 600 フレームのうち 491〜529 しか取れていない。原因を分けるために、`D3D11FrameTimer` に数え口（問い合わせの組がどれも結果待ちで測らなかったフレーム、読んだ組、`Disjoint` だった組）を一時的に足したビルド（`023c675` に足したもの。計測の後に消した）で、8 部分と 1 部分の全体表示を流した（19:45〜19:46、ほかのプロセスは 0.81〜0.98 コア）。

| 場面 | フレーム（暖機を含む） | 測らなかったフレーム | 読んだ組 | `Disjoint` | 場面が受け取った新しい時間 |
| --- | --- | --- | --- | --- | --- |
| 8 部分、1 回目 | 720 | 0 | 720 | 0 | 699 |
| 1 部分 | 720 | 0 | 720 | 0 | 720 |
| 8 部分、2 回目 | 720 | 0 | 719 | 0 | 678 |

- どのフレームも測られ、結果も読まれていた。欠けたのは、1 回の `Poll` で 2 つの組の結果が出て、`LastFrameTime` が新しいほうだけを残したフレームである（場面は 1 フレームに 1 回しか読まない）。1 部分の場面ではそれが 1 度も起きなかった。どの読み取りで 2 つの結果が出るかを決めるものは、この 3 回からは分けていない。2 回目で 1 つ読まれていない組は、最後のフレームの組である
- P-4 の合格の主張はこの部分集合に乗るが、欠けたフレームは、どのフレームとも同じ記録（全体表示）で、時間で選ばれて欠けたのではない（前のフレームと同じ読み取りで結果が出ただけ）

### 計測の条件のまとめ

- 段の時間は、どれも 1 フレームに 1 回の読み取りで、フレームの CPU 時間の一部である（走査の外の層の記録、配置、描画を含まない）
- 計測は 2 本目のコードで、係数と境目は設計の値（参照機と JIT の値）のままである。係数と境目の測り直しは 3 本目である
