# G3: ガイドの計測

行 G3（Issue #115）の計測の記録。設計書 §4.6 のガイド（目盛りの選び方・配置・ラベル）の CPU 時間を、要件 §5 の参照機で測った。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F、GeForce RTX 3060 Ti（ドライバ 610.88）、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。測った後に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、DirectWrite、倍率 1 |
| データ | 1e4 点の 1 系列（等間隔の X、シードつきの正弦波と雑音の `float` の Y）、ワーカー 2 本 |
| 仕様 | x と y の軸のタイトル、ラベルつきのレイヤー（凡例 1 行）、プロットのタイトル |
| 測る範囲 | `HeadlessRenderer.Render(PlotSpec)` の 1 回（コンパイル・配置・M4・記録・`Clear`・`Draw`）。1,500 フレームのうち最初の 50 を捨てた 1,450 フレーム。100 フレームごとに `ReadPixels` で GPU を待つ（測る範囲の外） |
| 場面 | ガイドあり（`Theme.Light`）とガイドなし（`ShowAxes`・`ShowGrid` が偽、`Padding` 0）の 2 つを、同じ仕様の描き直しと、毎フレーム新しい y の domain（`WithDomain`、ラベルが毎回変わる）の 2 つで |
| CPU | プロセスを固定しない回を 3 回と、論理プロセッサ 2 に固定して優先度 High の回を 1 回 |

## 結果

固定しない 3 回（中央値 / p95、µs）:

| 場面 | 1 回目 | 2 回目 | 3 回目 |
| --- | --- | --- | --- |
| ガイドあり・同じ仕様 | 149 / 329 | 180 / 342 | 209 / 532 |
| ガイドなし・同じ仕様 | 30 / 82 | 39 / 129 | 33 / 105 |
| ガイドあり・新しい domain | 476 / 583 | 522 / 700 | 498 / 961 |
| ガイドなし・新しい domain | 337 / 409 | 370 / 562 | 337 / 421 |

固定した 1 回（中央値 / p95、µs）: ガイドあり・同じ仕様 680 / 873、ガイドなし・同じ仕様 382 / 506、ガイドあり・新しい domain 976 / 1,159、ガイドなし・新しい domain 672 / 859。

- **同じ仕様の描き直し**で、ガイドは中央値で 110〜175 µs を足す。同じ仕様では配置も記録もやり直さない（§4.8 の差分）ので、これはガイドの命令を描く時間である。確かめるために、グリッドだけを消すと 34 µs、軸だけを消すと 68 µs 減った（ガイドあり 140 µs、グリッドなし 106 µs、軸なし 71 µs、ガイドなし 30 µs）。2 つの和はガイドの分とほぼ同じである。グリッドと目盛りは折れ線で、1 本につき 3 回描く（§5.3）
- **新しい domain**では、ガイドは中央値で 128〜152 µs を足す。そのうち命令を描く分は上の値と同じ大きさで、残り（数十 µs）が目盛りの選び方・配置・新しいラベルの書式と整形と計測である
- 固定した回はどの場面も 300〜550 µs 遅い。PR #108 で見た、プロセスの固定が GPU のドライバのスレッドも同じ論理プロセッサに乗せる影響と同じ向きである（`bench.mdc`）。ガイドの差（中央値で 298 µs と 304 µs）は、固定しない回より大きい
- 確保: 同じ仕様の描き直しと、2 つの domain の交互の描き直しは 0 バイト（テストの `Allocation_SameSpecAndTwoDomains_Nothing`）。新しいラベルの描き直しは確保する（§4.6 の「確保」、行 I1 で無くす）

## NativeAOT

| サンプル | main（`eb2a784`） | この PR |
| --- | --- | --- |
| `HelloPlot` | 1,778,176 B | 1,788,928 B（+10,752 B） |
| `SpecPlot` | なし | 2,154,496 B |

どちらも警告 0。`SpecPlot` はハードウェアと WARP、倍率 1 と 1.5 で 2 枚の PNG を書いた。

`HelloPlot` の増分は、ILC の map ファイル（`IlcGenerateMapFile`）の節の長さを名前で分けると、名前に `Rect` を含む節（シェーダのバイトコード `RectVS`・`RectPS` と `D3D11RectPipeline`）が +7,299 B、ほかの HyperPlot の節（`Draw` の段の切り替え、`RenderList.DrawRect`、矩形の段）が +1,687 B、メタデータが +227 B、ランタイムと BCL が +436 B で、節の和は +9,649 B である。ファイルの増分との差 1,103 B は、PE の節の揃えである。`HelloPlot` は `PlotSpec` を使わないので、ガイドのコード（目盛り・配置・テーマ）は入らない。
