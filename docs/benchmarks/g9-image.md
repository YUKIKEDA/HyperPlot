# G9: image の Geom の計測

行 G9（Issue #200）の計測の記録。設計書 §5.5.3 の image の Geom で、2 万 × 2 万の `float` のラスタ（1.6 GB、メモリマップ）を、ホストと同じ形（計画とバックエンドの常駐キャッシュ、1 フレーム 4 MB の予算）で描き、要件 P-1（CPU と GPU がそれぞれ p95 で 8 ms 以下）と比べた。要件 §5 の参照機で測った。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。Core の internal の計画と常駐キャッシュを読むため、データの道のハーネスの名前を借りた。測った後に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light`（軸・グリッド・カラーバーつき） |
| データ | 2 万 × 2 万の `float`（sin(x / 800) · cos(y / 600) + 0.05 以下の雑音、シード 9）を生のファイルに書き、`Column.MapFile<float>` で読む。ファイルはページキャッシュに載っている（書いた直後と、続けて走らせた回） |
| 色 | sequential の viridis（既定）、`Extent` は (0, 20,000, 0, 20,000) |
| 場面 | **全体**: ラスタ全体を表示し、y の domain を毎フレーム 1 ずつずらす（64 通り）。**パン**: 3,600 × 2,000 の範囲（1 画素に約 1.9 テクセル、段 0）を、毎フレーム右へ 40 ずつ動かす。**ズーム**: 全体から真ん中へ、毎フレーム範囲を 0.98 倍に縮める |
| フレーム | 最初の描画（ミップマップを作って待ち、最初のフレームを描く）の後、300 フレーム |
| 測る範囲 | CPU は `PlotPlan.Render`（記録と、送るタイルを常駐キャッシュに書く仕事）と `D3D11Backend.Draw`（送る仕事と描画）の和。GPU はフレームのタイムスタンプのクエリ。送る量は常駐キャッシュのそのフレームの書き込み（`BytesThisFrame`） |
| 回 | 場面の順に 1 回ずつを 3 回 |

## 結果

中央値 / p95（µs）。各欄は 1 回目、2 回目、3 回目。

| 場面 | CPU | GPU | 送る量（最大 / 平均） | 仮の描画のフレーム | 段・見えるタイル |
| --- | --- | --- | --- | --- | --- |
| 全体 | 483 / 768、443 / 584、459 / 596 | 277 / 284、268 / 274、276 / 284 | 3.81 MB / 0.02 MB | 1 / 300 | 段 4、25 |
| パン | 354 / 4,963、463 / 4,853、373 / 4,922 | 295 / 806、271 / 814、271 / 810 | 3.81 MB / 0.47 MB | 9 / 300 | 段 0、135 |
| ズーム | 328 / 4,685、348 / 4,938、296 / 4,868 | 256 / 722、256 / 720、259 / 731 | 3.81 MB / 0.34 MB | 24 / 300 | 段 0 まで |

- **ミップマップを作る時間**: 最初の描画は 862、897、898 ms（ミップマップの段 1〜6 をワーカーで作る仕事と、最初のフレームで見えるタイルを送る仕事）。段 1 から上のメモリは約 533 MB（元の 1.6 GB の約 1/3、設計 §3.7 の式どおり）
- **要件 P-1**: どの場面も CPU と GPU の p95 が 8 ms に収まる
- **CPU の p95**（パンとズームの約 4.9 ms）: タイルを送るフレームの時間である。予算いっぱいの 15 枚（3.81 MB）を送るフレームで、1 枚あたり約 0.3 ms は Core がタイルの 258 × 258 の値を常駐キャッシュの書き込みの領域へ写す仕事（`RasterPyramid.CopyTile` が要素ごとにチャンクを引く）である。タイルを送らないフレームの中央値は 0.3〜0.5 ms で、そのうち軸とカラーバーの配置と記録が約 0.3 ms（軸を隠した回で、全体の場面の CPU の中央値は 109 µs）
- **GPU の p95**（約 0.8 ms）: タイルを送るフレームの `UpdateSubresource` の分で、送らないフレームは約 0.27 ms
- **送る量**: どのフレームも 3.81 MB（`R32_FLOAT` の面 15 枚）以下で、要件 R-1 の「数 MB」に収まる。パンでは、毎フレーム 40 データ単位（約 21 画素）動かすと、平均 0.47 MB（約 2 枚）を送る
- **仮の描画**: 粗い段で仮に描いたフレームは、パンで 300 のうち 9、ズームで 24（段が変わるたびに、その段の見えるタイルが何フレームかで届く）。全体の場面は最初のフレームだけ
- **確保**: 300 フレームの最初のフレームで 4.2 MB（グリフのアトラスの最初の頁 2048² B を、カラーバーのラベルを初めて描くときに作る。行 T1 の頁）。そのほかは、ハーネスが時間を貯めるリストの伸び（4、8、16 … フレーム目）だけで、画像の描き直しの確保はない（テスト `ImageGeomTests.Warm_AllocatesNothing`）
- **GPU のクロック**: `nvidia-smi` の記録は取れなかった（ファイルが空だった）。GPU の時間はどの回も揃っている
