# G10: 座標系の flip の計測

行 G10（Issue #140）の計測の記録。設計書 §4.4 の cartesian の flip で、1 フレームの時間を flip のあり・なしで比べた。場面はロードマップの G10 の行と Issue #136 の Decision 7 のとおりで、要件 §5 の参照機で測った。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。測った後に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、ガイドなし（`ShowAxes`・`ShowGrid` が偽、`Padding` 0）。パネルは描画先の全体で、flip なしは x に沿って 1,920 画素列、flip ありは 1,080 画素行 |
| ワーカー | `PlotWorkerPool.Shared`（論理プロセッサの数 − 1）。プロセスの優先度は High、コアに固定しない |
| 1e9 点の線 | 行 S2 の場面: `samples/Shared/WalkFile.cs` の 1e9 点の `float` のメモリマップの列、X は `UniformColumn`。台本も S2 と同じ（全体から 100 万分の 1 まで 2^(1/8) 倍ずつ拡大し、2 倍ごとに 10 フレームのパン、全体へ戻る 531 フレーム）を 3 回、最初の 30 フレームを捨てた 1,563 フレーム。フレームごとに `ScaleX` の domain を台本の範囲にした仕様を描く。y の domain は学習（列の統計） |
| 1e7 点の area と bar | 等間隔の X、シードつきの正弦波と雑音の `float` の Y。行 G4 と同じく、毎フレーム新しい x の domain（データの 99〜100 % の 64 通り）。600 フレームのうち最初の 100 を捨てた 500 フレーム |
| 測る範囲 | CPU は `HeadlessRenderer.Render(PlotSpec)` の 1 回（コンパイル・M4・記録・`Clear`・`Draw`）。GPU はフレームのタイムスタンプのクエリ（`IGpuBackend.LastFrameTime`）。100 フレームごとに `ReadPixels` で GPU を待つ（測る範囲の外） |
| 回 | 線・area・bar の順に、それぞれ flip なし、flip ありを続けて 1 回ずつ。これを 2 回 |
| GPU のクロック | `nvidia-smi --query-gpu=timestamp,clocks.gr,pstate -lms 200` で記録した。105 回のうち P0（1,665 MHz）が 91 回。P5 と P8 の 14 回は、線の回の始まり（1e9 点のピラミッドを作る 1〜2 秒、GPU は休む。その回の最初のフレームで、捨てるフレームに入る）に当たる |

1e9 点のファイルは、この表より前の回で書いて読んだもの。ピラミッドは各回の最初のフレーム（捨てるフレーム）で作った。

## 結果

中央値 / p95（µs）。各欄は 1 回目、2 回目:

| 場面 | CPU（flip なし） | CPU（flip あり） | GPU（flip なし） | GPU（flip あり） |
| --- | --- | --- | --- | --- |
| 1e9 点の線 | 964 / 3,978、862 / 3,851 | 618 / 2,278、638 / 2,314 | 37 / 110、37 / 114 | 32 / 45、32 / 45 |
| 1e7 点の area | 1,650 / 1,888、1,692 / 1,920 | 1,010 / 1,761、978 / 1,096 | 154 / 158、154 / 158 | 150 / 154、150 / 154 |
| 1e7 点の bar | 1,702 / 2,534、1,466 / 1,611 | 952 / 1,518、874 / 995 | 112 / 114、111 / 114 | 62 / 64、63 / 64 |

- **CPU は flip ありのほうが短い**。M4 と画素列ごとの Geom は x に沿った画素の数だけ働き（§5.5.1・§5.5.3）、flip では 1,920 画素列が 1,080 画素行になる。中央値の比は線で 0.64・0.74、area で 0.61・0.58、bar で 0.56・0.60。減るのは x に沿った画素の数に比例する段だけなので、比は 1,080 / 1,920 = 0.56 を下回らない
- **記録の段の入れ替え**（§4.4）は、折れ線の点を CPU で 1 回なぞって横と縦を入れ替える。その数は M4 の出力（4H + 2 点まで）で抑えられ、上の CPU の時間はそれを含んだうえで flip なしより短い
- **GPU の bar**: 112 → 63 µs で、比 0.56 は矩形の数（画素列か画素行ごとに 1 つ）の比と同じである。塗る面積は flip で変わらない（1,920 列 × 高さ、高さは y の 1,080 画素の中、と、1,080 行 × 幅、幅は y の 1,920 画素の中）ので、この時間は矩形の数で決まっている
- **GPU の area**: 154 → 150 µs でほぼ同じ。`ColumnsVS` は台形の外接矩形を整数の画素に広げて描くので、画素シェーダの数は塗る面積で決まり、flip で変わらない。台形の数は 1,920 から 1,080 に減る
- **GPU の線**: 中央値は 37 → 32 µs。flip なしの p95 は回によって開き、この 2 回は 110・114 µs、同じハーネスでフレームごとの値を取った別の 4 回は 48〜52 µs だった（flip ありは 6 回とも 45 µs）。その 4 回で GPU の上位 5 % のフレームは、全体が見える拡大の始めと終わり（スパン 7e8〜1e9 点）と、`ReadPixels` の直後のフレームだった。p95 の差は flip なしの回どうしの幅と同じ大きさなので、比は出さない
- **確保**: 捨てたフレームの後、この表の回はどれも 0 バイト。前の回で、1e9 点の線に 1 回の走りで 1 フレームだけ 56 B が出た。段ごとに確保を数えるスクラッチの写しで 40 回走らせると、4 回出て、どれも `PlotWorkerPool.Extract` の中の `M4Batch.Wait`（`Monitor.Wait`）だった。`M4Batch` はこの PR で変えておらず、main にもある（行 G4 の記録の「確保の出どころ」）。Issue #141 で直す。温まった後の flip した仕様の描き直しは 0 バイト（`CoordFlipTests.Flip_Warm_AllocatesNothing`）
