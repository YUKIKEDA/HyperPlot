# I2c: 要素のヒットテストの計測

行 I2c（Issue #359）の計測の記録。設計 §9 の「要素のヒットテスト（行 I2c）」の項のとおり、要素の層への 1 回の `PlotEngine.HitTest` の CPU 時間を、要件 P-5（1e9 点で p99 1 ms 以下）と比べた。main は要素の層に答えないので、比べる相手は要件の値である。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F（16 スレッド）、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。エンジンの待つ口を使うため、データの道のハーネスの名前を借りた。測った後にデータと一緒に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light` |
| 数の x の棒 | `float` のメモリマップのファイル（`samples/Shared/WalkFile.cs` のランダムウォーク、1e9 行、4 GB、ページキャッシュに載っている）。x は `UniformColumn` |
| カテゴリの棒 | 同じ y の 1e9 行。カテゴリは行の番号を数で割った余りで、100 と 1e5（band が 1 画素未満） |
| 積み上げの棒 | 数の x（4 行に 1 つの x）、4 群、y はランダムウォークの絶対値。1e8 行（下の「積み上げの行の数」） |
| 矩形 | 131,072 個、シード 42 の位置（1,000 × 1,000 の中、辺は 10 以下） |
| 索引 | 待つエンジン（`WaitsForIndexes`）で 1 フレーム描いてから測る |
| 場面 | 全体表示。数の x の棒と積み上げは、ズームした表示（x の幅 7,680 行、1 画素に 4 行）も |
| カーソル | シード 42 の 1,000 か所（パネルの中の一様な位置）。`XY` の半径は 8 画素。設計 §9 の「棒の上の端」は測っていない: 数の x の棒の `XY` は窓ごとに 1 本だけを見るので、カーソルの y で仕事が変わらない |
| 測る範囲 | 1 回の `HitTest`（`Stopwatch.GetTimestamp`）。最初の 50 回は慣らしで数えない |
| 回 | 場面を順に 3 回（プロセスを場面ごとに起こす） |

## 結果

p50 / p99（ms）。各欄は 1 回目、2 回目、3 回目。

| 場面 | 表示 | `X` | `XY` |
| --- | --- | --- | --- |
| 数の x の棒 1e9 | 全体 | 0.0007 / 0.0012、0.0009 / 0.0013、0.0007 / 0.0013 | 0.052 / 0.073、0.049 / 0.079、0.053 / 0.109 |
| 数の x の棒 1e9 | ズーム | 0.0004 / 0.0008、0.0003 / 0.0004、0.0006 / 0.0066 | 0.0067 / 0.0077、0.0061 / 0.0073、0.0067 / 0.0073 |
| カテゴリの棒 1e9（100） | 全体 | 0.0002 / 0.0002（3 回とも） | 0.0002 / 0.0003（3 回とも） |
| カテゴリの棒 1e9（1e5） | 全体 | 0.0006 / 0.0011、0.0008 / 0.0014、0.0008 / 0.0019 | 0.0041 / 0.0060、0.0066 / 0.0156、0.0044 / 0.0083 |
| 積み上げの棒 1e8（4 群） | 全体 | 0.0033 / 0.0071、0.0057 / 0.0094、0.0054 / 0.0096 | 0.127 / 0.181、0.135 / 0.319、0.140 / 0.307 |
| 積み上げの棒 1e8（4 群） | ズーム | 0.0008 / 0.0009、0.0009 / 0.0010、0.0009 / 0.0010 | 0.0042 / 0.0046、0.0047 / 0.0051、0.0047 / 0.0052 |
| 矩形 131,072 | 全体 | 0.32 / 0.41、0.31 / 0.37、0.32 / 0.56 | 0.35 / 0.48、0.33 / 0.49、0.33 / 0.49 |

- **要件 P-5**: どの場面も p99 は 1 ms を下回った。最も重いのは矩形（全部を調べる）で、p99 0.56 ms 以下
- **矩形の最初の形**: 最初の実装は、各矩形で `Math.Min`・`Math.Max` と平方根を使い、p99 が `X` で 1.3 ms、`XY` で 2.6〜3.0 ms と要件を超えた
  - 平方根をやめて距離の 2 乗で比べ、NaN を「下 ≤ 上」の比較 1 回で退けると、0.78〜1.04 ms になった
  - 次に、x の範囲だけで退けられる矩形を `Vector<double>` の幅でまとめて飛ばした（`X` はカーソルの x を含むか、`XY` は半径の内か）。0.37〜0.56 ms になった
- **カテゴリの棒**: カテゴリの下か最も近いカテゴリを計算で求め、その極値の行を読むだけなので、100 カテゴリでは定数の時間。1e5 カテゴリ（band が 1 画素未満）は、画素列の区間の極値をピラミッドで引く
- **数の x の棒の `XY`**: 1 画素列に約 52 万行あり、窓ごとにピラミッドの極値で最も伸びた棒を 1 本だけ見るので、p99 0.11 ms 以下
- **積み上げの棒の `XY`**: 4 群のそれぞれが数の x の棒と同じ探索をするので、数の x の棒の約 4 倍

## 積み上げの行の数

設計 §9 は積み上げの棒を 1e9 行としていた。数の x の積み上げは、積み上げの表（各群の x の和集合と、群ごとの正と負の累積の列）を作る（§5.5.3）。1e9 行では、これと元の列（x の `double`、y の `float`、群の番号）が参照機のメモリ（48 GB）に収まらない見込みなので、1e8 行で測った。探索は群ごとに数の x の棒と同じで、行の数には対数でしか依らない。そのため、1e9 行の時間は数の x の棒の 1e9 行の結果と同じ形になる（`X` は 1 群あたり p99 0.0013 ms、`XY` は p99 0.11 ms の 4 群分）。
