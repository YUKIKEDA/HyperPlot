# I2a: ヒットテストの計測

行 I2a（Issue #341）の計測の記録。設計 §9 の「ヒットテスト（行 I2a）」の項のとおり、1 回の `PlotEngine.HitTest` の CPU 時間を、要件 P-5（1e9 点で p99 1 ms 以下）と比べた。main にこの API はないので、比べる相手は要件の値である。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F（16 スレッド）、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。エンジンの待つ口を使うため、データの道のハーネスの名前を借りた。測った後にデータと一緒に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light` |
| データ | `float` のメモリマップのファイル（`samples/Shared/WalkFile.cs` のランダムウォーク、1 本 1e9 点で 4 GB、ページキャッシュに載っている）。x は `UniformColumn`。線の層が 1 本か 4 本 |
| 索引 | 待つエンジン（`WaitsForIndexes`）で 1 フレーム描き、ピラミッドを作り終えてから測る |
| 場面 | 全体表示と、ズームした表示（x の幅 7,680 点、1 画素に 4 点） |
| カーソル | シード 42 の 1,000 か所。パネルの中の一様な位置と、系列 0 の線の上（その x の行の y）。`XY` の半径は 8 画素 |
| 測る範囲 | 1 回の `HitTest`（`Stopwatch.GetTimestamp`）。最初の 50 回は慣らしで、数えない |
| 回 | 1 本と 4 本を交互に 3 回（プロセスを 6 度） |

- **要件 P-5**: どの場面も p99 は 1 ms を下回った。最も重いのは、4 本の全体表示でカーソルが線の上にあるときの `XY` で、p99 0.45〜0.60 ms、最大 0.84 ms だった
- **`X`**: 系列ごとに x の二分探索（一様な x は計算）と、NaN を飛ばすピラミッドの探索だけなので、4 本の全体表示でも p99 0.006 ms 以下
- **`XY` の全体表示**: 1 画素列に約 52 万点がある
  - 最初の実装は、カーソルに最も近い点をきっちり探し、4 本の全体表示で p99 66 ms だった。ランダムウォークは 1 画素列の中でカーソルの y を数百回横切り、どの横切りも極値では退けられないため、全部を読んでいた
  - 範囲の x の幅を最初と最後の行から取って下界に入れ、半画素の誤差を許すと（Issue #341 の決定 5）、p99 0.6 ms 以下になった
- **ズーム**: 1 画素に 4 点なので、半径の画素列の範囲は短く、0.04 ms 以下
- 最大の値は、プロセスのほかのスレッドとの取り合いで、1 回だけ伸びたものである（同じ場面の p99 は低い）
