# G5c: Stat の計測

行 G5c（Issue #226）の計測の記録。設計書 §5.5.3 の Stat の仕事（density の帯域幅と格子への配り、smooth の窓の和、bin 2D のセルの数）を 1e9 行で、ホストと同じ形（`HeadlessRenderer`、ハードウェアの D3D11）で測り、要件 P-2（構築は 1 GB/s 以上）と P-1（1 フレームの p95 が 8 ms 以下）と比べた。要件 §5 の参照機で測った。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。カテゴリの番号から列を作る internal の口を使うため、データの道のハーネスの名前を借りた。測った後に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light` |
| ワーカー | `PlotWorkerPool.Shared`（15 スレッド）。プロセスの優先度は High |
| データ | 1e9 行。x と y は `float` のメモリマップのファイル（4 GB ずつ、一様な値 4 つの和 × 25、シード 5 と 6。ページキャッシュに載っている）。群は `int` の番号（4 GB）で、行 i の番号は i · 2654435761 mod 8。smooth の x は `UniformColumn`（0 から 1 刻み） |
| 場面 | **density**: x の line と `Stat.Density()`（帯域幅は自動の `bw.nrd0`）か `Stat.Density(0.5)`（帯域幅を与える）、1 群と、群 8 つを `ColorBy`。**smooth**: `UniformColumn` の x と `float` の y の line と `Stat.Smooth(1e7)`（512 点）。**bin 2D**: x と y の rect と `Stat.Bin2D()`（既定の区切り）か、`Stat.Bin2D(Stat.Bin(step: 1/3), Stat.Bin(step: 1/3))`（範囲 0〜100 で 300 × 300、9 万セル） |
| 測る範囲 | **最初の描画**: 新しい計画で最初の `Render`（Stat の仕事と 1 フレーム）。**作り直し**: 値の列（density と bin 2D は x、smooth は y）を `Invalidate` した直後の `Render`（3 回の中央値）。**フレーム**: 2 秒描いて温めた後の 300 フレーム（y の domain を毎フレーム変え、記録をやり直す）。CPU は `Render` の 1 回、GPU はフレームのタイムスタンプのクエリ、確保は `Render` の前後の `GC.GetAllocatedBytesForCurrentThread()` の差の和 |
| 回 | 場面の順に 1 回ずつを 3 回。確保は、ハーネスを直した後（下）にもう 1 回 |

## 結果

ワーカーの仕事はミリ秒、フレームは中央値 / p95（µs）。各欄は 1 回目、2 回目、3 回目。

| 場面 | 最初の描画 | 作り直し | フレームの CPU | フレームの GPU | 確保（300 フレーム） |
| --- | --- | --- | --- | --- | --- |
| density（1 群、帯域幅は自動） | 10,593、9,355、10,100 | 10,889、9,556、10,917 | 364 / 506、352 / 408、462 / 673 | 185 / 189、185 / 191、185 / 190 | 0 B |
| density（1 群、帯域幅 0.5） | 2,779、2,742、2,846 | 1,963、1,762、2,068 | 373 / 520、349 / 397、520 / 798 | 185 / 189、185 / 189、185 / 189 | 0 B |
| density（8 群、帯域幅は自動） | 10,878、9,340、12,961 | 11,154、9,513、12,616 | 758 / 866、480 / 521、756 / 867 | 313 / 317、310 / 314、312 / 316 | 56 B（1 回） |
| density（8 群、帯域幅 0.5） | 3,034、2,979、3,131 | 2,072、2,167、2,165 | 573 / 820、855 / 1,038、686 / 884 | 312 / 316、312 / 318、313 / 316 | 0 B |
| smooth | 2,486、2,328、2,434 | 2,321、2,471、2,289 | 325 / 358、325 / 364、359 / 593 | 174 / 179、173 / 178、174 / 178 | 0 B |
| bin 2D（既定の区切り） | 5,737、6,384、5,810 | 3,166、3,368、3,213 | 259 / 392、246 / 361、210 / 236 | 213 / 216、212 / 216、211 / 215 | 0 B |
| bin 2D（300 × 300） | 6,447、6,281、5,945 | 3,746、3,541、3,231 | 3,964 / 4,600、4,051 / 4,528、4,022 / 4,367 | 925 / 1,735、574 / 1,093、1,053 / 1,635 | 0 B |

- **density（帯域幅を与える）**: 作り直しは約 1.8〜2.1 s。範囲は列の統計から決まり、なめるのは格子へ配る 1 回だけで、1 群は値 4 GB を約 2.1 GB/s、8 群は値と番号の 8 GB を約 3.9 GB/s で読む（要件 P-2 を超える）
- **density（帯域幅は自動）**: 約 9.5〜12.6 s。`bw.nrd0` のために、平均と平方和の 1 回、IQR の radix select（`float` で 4 段）、配りの 1 回で 6 回なめる（1 群で 24 GB、8 群で 48 GB）。1 回あたりは 1 群で約 2.4 GB/s、8 群で約 4.4 GB/s と P-2 を超え、時間はなめる回数で決まる（行 G5b の quantile と同じ）。帯域幅を与えれば 1 回で済む（設計 §4.1）
- **smooth**: 約 2.3〜2.5 s。y の 4 GB を読み（x は `UniformColumn` で計算する）、行ごとに窓の端 1,024 個の二分探索をする。約 1.7 GB/s
- **bin 2D**: 作り直しは約 3.2〜3.7 s で、x と y の 8 GB を約 2.4 GB/s で読む。区切りの数（既定と 300 × 300）で時間はほとんど変わらない。最初の描画の約 2.5 s 多い分は、y のファイルの最初の読み出しと列の統計
- **フレーム**: どの場面も P-1 に収まる。描くのは点の数 × 群（density と smooth は 512 点）か、数 0 でないセル。bin 2D の 300 × 300 は 9 万個の rect をセルの値の色で毎フレーム記録し、CPU の p95 が 4.4〜4.6 ms。行 G7c の計測（`docs/benchmarks/g7c-color.md`）の、色で塗る rect 131,072 個の約 6 ms を数で割った見込み（約 4.1 ms）と合う
- **確保**: 1 回目から 3 回目は 300 フレームで約 86 KB と出た。ハーネスが毎フレーム作る仕様（y の domain を変えた `PlotSpec`）と、時間を入れる `List<double>` の伸びを数えていたので、`Render` の前後だけを数えるように直して測り直した（行 G5b のヒストグラムと Stat のない線でも、直す前は同じ 8,352 B だった）。直した後は 0 B で、density（8 群、帯域幅は自動）だけが 300 フレームに 1 回 56 B を確保した。行 G5a で見つけた、分けた area の 1 回の 56 B（Issue #210、未解決）と同じ形で、分けた line でも起きる
