# I3a: 選択の計測

行 I3a（Issue #368）の計測の記録。設計 §9 の「選択（行 I3a）」の項のとおり、3 つを測った。X の範囲の行の区間は要件 P-5（p99 1 ms 以下）、強調したマウスだけのフレームは要件 P-6（p95 2 ms 以下）と比べる。矩形のビット列は要件に数がないので記録だけである。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F（16 スレッド）、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。エンジンの待つ口を使うため、データの道のハーネスの名前を借りた。測った後にデータと一緒に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light` |
| データ | `float` のメモリマップのファイル（`samples/Shared/WalkFile.cs` のランダムウォーク、1 本 1e9 点で 4 GB、ページキャッシュに載っている）。x は `UniformColumn`。線の層が 1 本か 4 本 |
| 索引 | 待つエンジンで 1 フレーム描いてから、待たないエンジンにして測る |
| X の範囲 | シード 42 の 1,000 の範囲（両端が一様）で、層 0 の `SelectedRowsAsync` が終わるまで。最初の 50 回は慣らし |
| 矩形のビット列 | x の中央の半分と、y のビューの中央の半分の矩形で、全部の層の `SelectedRowsAsync` を同時に始め、全部が終わるまで。ワーカーの数は既定（`PlotWorkerPool.Shared`）。同じプロセスで 3 回 |
| 強調したフレーム | x の中央の 10 % の X の範囲を選び、行 I2b のホバーの場面と同じ台本でマウスを 330 フレーム動かす（最初の 30 は数えない）。CPU 時間は移動と `RenderFrame`、GPU 時間は `LastFrameTime` |
| 回 | 1 本と 4 本を交互に 3 回（プロセスを 6 度） |

## 結果

| 系列 | X の範囲の区間 p50 / p99（ms） | 矩形のビット列（秒、3 回） | 強調したフレームの CPU p50 / p95（ms） | GPU p50 / p95（ms、時間の届いたフレーム） |
| --- | --- | --- | --- | --- |
| 1 本、1 回目 | 0.0003 / 0.0045 | 1.57、1.58、1.63 | 0.423 / 0.843 | 0.428 / 0.657（21） |
| 1 本、2 回目 | 0.0002 / 0.0032 | 1.70、1.88、1.85 | 0.395 / 0.577 | 0.425 / 0.463（30） |
| 1 本、3 回目 | 0.0002 / 0.0034 | 1.62、1.86、1.87 | 0.396 / 0.469 | 0.431 / 0.556（22） |
| 4 本、1 回目 | 0.0002 / 0.0050 | 6.25、6.71、7.27 | 0.615 / 1.446 | 0.910 / 1.063（53） |
| 4 本、2 回目 | 0.0002 / 0.0034 | 7.19、7.16、7.47 | 0.753 / 0.866 | 0.935 / 0.997（27） |
| 4 本、3 回目 | 0.0002 / 0.0055 | 7.30、7.27、7.24 | 0.777 / 0.952 | 0.958 / 1.004（22） |

- **要件 P-5**: X の範囲の区間は、x の二分探索が 2 回なので、p99 0.0055 ms 以下だった
- **要件 P-6**: 強調したマウスだけのフレームの p95 は、CPU が 1.45 ms 以下、GPU が 1.06 ms 以下で、2 ms を下回った
- **強調の GPU 時間**: 行 I2b のマウスだけのフレーム（1 本 0.05 ms、4 本 0.10 ms）より、1 本で約 0.38 ms、4 本で約 0.85 ms 長い。選んだ x の範囲で切り抜いた線を、2 倍の太さで描き直す分である。切り抜きは画素の段で働くので、描き直す折れ線は各層の M4 の出力の全部（4W 点）で、その線の描画の時間がかかる
- **矩形のビット列**: 1e9 点で 1 本 1.6〜1.9 秒、4 本で 6.3〜7.5 秒（層ごとにほぼ同じ時間で、4 つは同じワーカーを分け合う）
  - ピラミッドを作る時間（同じ参照機で 1e9 点に約 0.4 秒。行 I2b の計測で、エンジンが 1 本のピラミッドを作り終えて描くまでの時間）より約 4 倍長い
  - ビット列の仕事は、行ごとに列の仮想の `DifferenceAt` を呼んで値を 1 つずつ読む。ピラミッドはチャンクを 1 度に読んで、まとめて畳む。その読み方の違いである
  - 要件に数はないので、この PR では記録にとどめる
- **数えた行**: 1 本は 500,000,001 行（x の範囲の行のすべての y が、y の中央の半分に入った）、4 本は 895,965,539 行
- **GPU 時間の届いたフレーム**: 300 のうち 21〜53 で少ない。時間は数フレーム後に届き、クエリの組が空いていないフレームは時間を持たない（設計 §5.2）
