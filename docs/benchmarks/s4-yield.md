# S4: 競合の横での構築の計測

行 S4（Issue #421）の計測の記録。設計書 §9 の「CPU の配分」の場面を、要件 §5 の参照機で測った。全論理プロセッサを使う競合の横で 1e9 点の空間タイル索引を構築し、何もしないプールと、混み具合を測って休むプール（PR #423 の設計）を比べた。結果から、譲る仕組みは作らないと決めた（`docs/adr/0003-no-yield.md`）。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Intel Core i5-13400F（16 スレッド）、48 GB、Windows 11 |
| ビルド | `HyperPlot.DataPath` の NativeAOT Release（win-x64、2,358,272 B、発行の警告 0）、.NET SDK 10.0.403、ブランチ `feat/421-yield` のコミット `2c83dc7`（main には入れていない）。プロセスの優先度は通常 |
| データ | 一様な分布の 1e9 点の `float` の x と y（`generate-points` の既定の種）。ページキャッシュに載った状態 |
| ワーカー | 8 本 |
| 競合 | `burn` の場面: 論理プロセッサと同じ数（16 本）のスレッドが通常の優先度で空回りし、1 秒ごとに回った数を書く子プロセス。構築の前の 8 秒の速さを 100 % とする |
| 回 | 競合つきは、休まない、休みの段の上限（`MostRest`）1・2・3 の順を 2 巡。1 回は 25 分で打ち切った。競合なしは、休むプールと休まないプールを交互に 3 回ずつ |
| 機械の状態 | 静かな機械の値ではない。計測のあいだ、ほかのプロジェクトの試験が動いていた（`watch-machine.ps1` の記録で、競合つきの計測の終わりごろに 5 秒あたり 7〜23 コア秒）。競合なしの計測では、休むプールの読みで、ほかが 1.4〜5.3 コアを使っていた |

## 再現

```powershell
git switch feat/421-yield
$env:PATH = "C:\Program Files (x86)\Microsoft Visual Studio\Installer;" + $env:PATH
dotnet publish benchmarks/HyperPlot.DataPath -c Release -r win-x64 -o .dev/s4-datapath
.dev/s4-datapath/HyperPlot.DataPath.exe generate-points --file .dev/s4-points --points 1000000000
./benchmarks/HyperPlot.DataPath/watch-machine.ps1 -Log .dev/machine.log -Seconds 5     # 別の PowerShell で
.dev/s4-datapath/HyperPlot.DataPath.exe yield --file .dev/s4-points --workers 8 --yields off --competitor --collects
.dev/s4-datapath/HyperPlot.DataPath.exe yield --file .dev/s4-points --workers 8 --yields on --most-rest 1 --competitor --collects
```

## 競合の横での構築（1e9 点）

| プール | 巡 | 構築 | 構築が使ったコア | 競合の速さ | `GC.Collect()` の最大 | 16.7 ms を超えたフレーム（最大） |
| --- | --- | --- | --- | --- | --- | --- |
| 休まない | 1 | 96.9 秒 | 3.65 | 79.4 % | 44.7 ms | 0（0.2 ms） |
| 休まない | 2 | 103.9 秒 | 3.47 | 79.6 % | 80.3 ms | 0（2.0 ms） |
| 休む、上限 1 | 1 | 785.6 秒 | 0.39 | 100.0 % | 24.3 ms | 1（30.0 ms） |
| 休む、上限 1 | 2 | 1,178.6 秒 | 0.30 | 100.5 % | 54.6 ms | 1（61.7 ms） |
| 休む、上限 2 | 1 | 25 分で打ち切り | | | | |
| 休む、上限 2 | 2 | 804.6 秒 | 0.44 | 106.5 % | 10.8 ms | 0（5.2 ms） |
| 休む、上限 3 | 1 | 25 分で打ち切り | | | | |
| 休む、上限 3 | 2 | 25 分で打ち切り | | | | |

- フレームは、構築中の 16.7 ms ごとの `Acquire`・`Count`・`Release` の時間である。`GC.Collect()` は、別のスレッドから 2 秒ごとに呼んだ
- 競合の速さが 100 % を超える回があるので、この値には数 % のゆれがある
- 休むプールの読みでは、ほかが 15.4〜15.5 コア、ワーカーが 0.5〜0.6 コアを使い、休みの段は上限に張り付いていた
- 上限 1 の 1 巡目は、休みが 17,700 回で合計 300.4 秒だった。ワーカー 8 本の延べは 6,285 秒、構築のプロセスが使った CPU は約 310 秒である。残りの約 5,670 秒をワーカーがどこで待ったかは、突き止めていない
- 段ごとの時間は、どの段も同じ程度に延びた（上限 1 の 1 巡目と休まない 1 巡目の比: 範囲 5.7 倍、最初の走査 7.3 倍、書き込み 8.9 倍、密度タイル 6.3 倍）

## 競合の横での構築（1e8 点）

同じビルドで、`GC.Collect()` を呼ばずに 2 回ずつ測った。

| プール | 構築 | 構築が使ったコア | 競合の速さ |
| --- | --- | --- | --- |
| 休まない | 10.1 秒 | 2.18 | 105.5 % |
| 休む、上限 1 | 42.2 秒 | 0.45 | 90.3 % |
| 休まない | 8.4 秒 | 2.36 | 77.4 % |
| 休む、上限 1 | 18.6 秒 | 0.97 | 106.8 % |

10 秒ほどの構築では、競合の速さは回ごとに大きく動く（休まないプールで 77 % と 105 %）。

## 競合のない構築（1e9 点）

休むプール（上限は既定の 4）と休まないプールを交互に測った。ほかのプロセスが CPU を使っていたので、空いた機械の比較にはなっていない。

| プール | 構築 | 休みの回数と合計 | 16.7 ms を超えたフレーム（最大） |
| --- | --- | --- | --- |
| 休む | 75.2 秒 | 0 回 | 0（0.4 ms） |
| 休まない | 51.4 秒 | | 0（0.2 ms） |
| 休む | 60.4 秒 | 1,551 回、26.6 秒 | 0（0.2 ms） |
| 休まない | 63.1 秒 | | 1（86.4 ms） |
| 休む | 61.5 秒 | 858 回、16.1 秒 | 0（7.4 ms） |
| 休まない | 55.0 秒 | | 0（8.3 ms） |

## 測らなかったもの

譲る仕組みを作らないと決めたので、次は測っていない: `MostRest` が 4 と 6 の回、既定の数（15 本）のワーカー、End-to-end の場面のフレーム、書き込みの段の途中の `Dispose`、読みの費用、Linux（WSL2）、静かな機械での比較。
