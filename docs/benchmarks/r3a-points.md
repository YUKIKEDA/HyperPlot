| 項目 | 値 |

## 確保 0 の試験で見つけたもの

`MarkerTests.RecordAndDraw_SteadyState_AllocatesNothing`（WARP、Debug）が、D3D11 の試験の全体を別のビルドと並べて走らせたときだけ、248 B か 744 B を数えた（8 回のうち 4 回）。単独では出ない。

- 段ごとに数えると、確保はフレームの最初の `DrawMarkers` の中だけだった（1 フレームに 248 B、5 フレームのうち 1〜3 フレーム）
- `DrawMarkers` の引数の検査の `Enum.IsDefined(style.Shape)` を、名前の比較に置き換えると、同じ条件の 6 回すべてで 0 B になった
- `Enum.IsDefined` の列挙の表が、GC の後の最初の呼び出しで作り直されると読んでいる。置き換えで消えたことからの読みで、ランタイムのコードは読んでいない
- 注釈の検査（`PlotPlan.Annotations.cs`）にも `Enum.IsDefined` が 3 か所ある。Issue #400（992 B）の手がかりとして、その Issue に書いた

### P-4 の判定

判定は、1 フレームの CPU 時間と GPU 時間の和が p95 で 16.7 ms 以下（Issue #431 の決定 27）。

- **収まる**: 一様な 1e7 点は、直径 2 DIP と 6 DIP、不透明と不透明度 0.6 のどれも 8.5〜13.9 ms。中央の塊は直径 2 DIP で 9.1 ms。台本は 10.4〜16.1 ms。64 カテゴリは 15.8〜16.2 ms
- **収まらない**: 点が重なる 3 つの全体表示である。中央の塊の直径 6 DIP の不透明度 0.6（18.2 ms）、同じ塊の不透明（GPU 時間だけで p95 19.2 ms）、8 カテゴリの直径 6 DIP の不透明度 0.6（17.5〜17.6 ms）
- 収まらない場面の扱いは、行 R3b に送る（オーナーの決定、2026-11-13）。行 R3b は密度との切り替えを作る行で、重なりの多い画面を密度に切り替えるか（点の数 × 印の面積での判定）をそこで決める

### ページの中の並び

最初の実装は、ページの点を写しの順（Morton 順）のまま置いた。その GPU 時間（コミット `e06ed9f`、同じ条件の全体表示、p50 / p95）と、ページの中を歩幅 104,729 で並べ替えた後（上の表）を並べる。

| 場面 | 写しの順 | 並べ替えた後 |
| --- | --- | --- |
| 一様、直径 2 DIP、不透明 | 7.3 / 7.6〜7.8 ms | 7.29 / 7.69 ms |
| 一様、直径 6 DIP、不透明 | 16.7〜16.8 / 17.1〜17.3 ms | 12.45 / 12.96 ms |
| 一様、直径 6 DIP、不透明度 0.6 | 15.6 / 16.0〜16.2 ms | 11.63〜11.79 / 12.11〜12.28 ms |
| 中央の塊、直径 2 DIP、不透明 | 13.0 / 13.4 ms | 7.82 / 8.21 ms |
| 中央の塊、直径 6 DIP、不透明度 0.6 | p50 29.3〜29.8 ms | 17.04 / 17.56 ms |

- 写しの順では、隣の点が 1 画素以内にあり、続けて描く印がほぼ同じ画素に重なる。並べ替える範囲を変えた計測（JIT の Release、一様・直径 6 DIP・不透明度 0.6、GPU 時間の p50）: 並べ替えなし 15.6〜16.6 ms、16 点ごと 15.8 ms、256 点ごと 15.9〜16.1 ms、4,096 点ごと 14.5〜14.7 ms、ページ（65,536 点）ごと 11.3〜12.1 ms、4 ページをまとめて 18.3 ms、16 ページ 18.8 ms、全部（152 ページ）20.9 ms
- 範囲が狭いと遅く、ページをまたいで広げても遅い。なぜその間が速いのか、GPU の中の理由は確かめていない。測った範囲で最も速いページごとを取った
- 8 カテゴリが 1 つの部分より遅い（16.4 ms と 11.7 ms）のも、同じ関係の中にある。8 つに分けると、1 ページの点が画面の 8 倍の広さに散る。これは「4 ページをまとめて」の並び（18.3 ms）に近い
- ピクセルシェーダは原因でない。色を返すだけのシェーダに替えても速くならなかった（JIT、21.1 ms。印の四角の全部を塗るので、円より塗る画素が多い）
- 並べ替える前に確かめて、違いが出なかったもの: エンジンを通さない直接の描画（直径 6 DIP で 15.2 ms）、描く先の形式、シェーダの分岐、セルの大きさ

### 最初の表示まで

仕様を渡してから、索引ができて、全体表示のページが全部常駐するまで（暫定の印が消えるまで）。フレームは 1 ms の待ちを挟んで続けて描いた。

| 一様、1 つの部分（7 回） | 0.64〜0.68 秒 | 40〜43 | 31 | 153（120 MB） |
| 中央の塊、1 つの部分（4 回） | 0.64〜1.02 秒 | 34〜42 | 31 | 153（120 MB） |

- 最初のページが出るまで（索引の構築）は、1 つの部分で 0.18〜0.22 秒（中央の塊の 1 回は 0.56 秒）、8 カテゴリで 0.43〜0.46 秒、64 カテゴリで 1.04 秒。部分の索引は 1 つずつ順に作る

### 目盛りの基準

常駐の点の位置の基準は、常駐のセル（32,768 点以下）のままにする。葉（4,096 点以下）に取ると、セルの表は葉の数（1e7 点で最大 50,000）になる。試作では、セルが 1,024 個から 50,176 個になると、フレームの CPU 時間が p50 で 0.14〜0.22 ms から 0.54 ms（p95 1.1〜1.4 ms）に増えた（Issue #438 の最初の計測）。点が重なる場面は 16.7 ms を超えていて、足せる時間がない。葉に取って救えるのは、4,096〜32,768 点の小さな塊を 3,000 万倍まで拡大したときの点の寄りだけである（設計書 §5.5.2 の「限界」）。
