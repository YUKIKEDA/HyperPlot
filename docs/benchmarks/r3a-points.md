# R3a: 散布の生の点の計測

行 R3a の計測の記録。設計書 §9 の「散布の生の点」の場面を、要件 §5 の参照機で測る。行 R3a は 2 本の PR に分かれていて、この記録は 1 本目（Issue #437、CPU の道）の分である。索引の道と要件 P-4 の判定は、2 本目（Issue #438）で足す。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Intel Core i5-13400F（16 スレッド）、48 GB、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | `HyperPlot.E2E` の NativeAOT Release（win-x64、3,424,768 B、発行の警告 0）、.NET SDK 10.0.403、ブランチ `feat/437-point-cpu`。プロセスの優先度は高 |
| 場面 | `points`: 131,072 点の point の層 1 つを `PlotEngine` で 1,920 × 1,080 に描く。定義域は [0, 100]² |
| データ | シードつき（`Random(1)`）。一様（[0, 100]²）と、中央の塊（中心 (50, 50)、標準偏差 10 の正規分布） |
| 台本 | 1 周 300 フレーム: 動く中心のまわりで、全体から 10 分の 1 の幅まで拡大して戻る。暖機 30 フレームの後の 600 フレーム（2 周）を測る |
| フレームの間隔 | 16.7 ms 以上空ける（`Thread.Sleep`）。実際の間隔は 27.5〜28.5 ms だった（待ちの刻みが 15.6 ms のため） |
| ヒットテスト | 全体表示で、シードつきの 1,000 か所。X のモードと XY のモード、半径 8 DIP。2 巡して 2 巡目を読む |

## CPU の道（131,072 点）

| 場面 | CPU 時間 p50 / p95 / p99 / 最大 | GPU 時間 p50 / p95 / p99 / 最大 |
| --- | --- | --- |
| 直径 6 DIP、不透明、一様（1 回目） | 1.97 / 2.71 / 3.30 / 3.85 ms | 2.65 / 4.75 / 5.87 / 6.39 ms |
| 直径 6 DIP、不透明、一様（2 回目） | 1.87 / 3.07 / 3.35 / 4.18 ms | 2.64 / 5.44 / 6.39 / 7.53 ms |
| 直径 6 DIP、不透明度 0.6、中央の塊 | 1.76 / 2.10 / 2.47 / 3.24 ms | 2.79 / 5.00 / 5.50 / 6.73 ms |
| 直径 2 DIP、不透明、一様 | 1.87 / 2.43 / 3.11 / 4.39 ms | 2.52 / 4.51 / 5.13 / 5.92 ms |

- CPU 時間は、ビューを動かして `RenderFrame` が戻るまで。131,072 点を毎フレーム倍精度で写して記録する時間を含む
- GPU 時間は `LastFrameTime`（タイムスタンプの問い合わせ）で、600 フレームのうち 596 フレームの標本。毎フレーム 131,072 個の記録（4 MB）を送る分を含む
- CPU 時間と GPU 時間の p95 の和は 7.1〜8.5 ms で、16.7 ms に収まる
- GPU のクロックは記録していない。P-4 の判定（2 本目）では並べて書く

## 確保

| 範囲 | 確保 |
| --- | --- |
| 暖機の後の 600 フレーム（台本 2 周） | 52,256 B（どの場面でも同じ） |
| 最後の 300 フレーム（前に描いた表示の繰り返し） | 0 B |

- 確保があったのは 49 フレームで、最後は 280 フレーム目（台本の 1 周目）だった。900 フレーム（3 周）流しても、52,256 B と 49 フレームは変わらない
- 1 周目は、ビューが動くたびに新しい目盛りのラベルが出る。ラベルの文字列と整形は、初めて出るときに 1 度確保する（不変条件 3 の例外、行 I1c）。同じ表示を繰り返す 2 周目からは 0 B である

## ヒットテスト（131,072 点、要件 P-5 の 1 ms と比べる）

| 場面 | X のモード p50 / p99 / 最大 | XY のモード p50 / p99 / 最大 |
| --- | --- | --- |
| 直径 6 DIP、一様（1 回目） | 0.065 / 0.074 / 0.095 ms | 0.070 / 0.080 / 0.168 ms |
| 直径 6 DIP、一様（2 回目） | 0.066 / 0.086 / 0.197 ms | 0.071 / 0.083 / 0.179 ms |
| 直径 6 DIP、中央の塊 | 0.077 / 0.245 / 0.395 ms | 0.078 / 0.258 / 0.390 ms |
| 直径 2 DIP、一様 | 0.059 / 0.082 / 0.138 ms | 0.061 / 0.084 / 0.155 ms |

- どの場面でも p99 は 0.26 ms 以下で、1 ms に収まる。全部の点を調べる形なので、時間は点の数で決まる
- 中央の塊は p99 が一様の約 3 倍である。カーソルが塊の中にあると、半径の中の点が多く、比べる回数が増える（XY のモードで見つけた数は、一様 4,000 に対して塊 2,904。塊の外のカーソルは何も見つけない）

## 確保 0 の試験で見つけたもの

`MarkerTests.RecordAndDraw_SteadyState_AllocatesNothing`（WARP、Debug）が、D3D11 の試験の全体を別のビルドと並べて走らせたときだけ、248 B か 744 B を数えた（8 回のうち 4 回）。単独では出ない。

- 段ごとに数えると、確保はフレームの最初の `DrawMarkers` の中だけだった（1 フレームに 248 B、5 フレームのうち 1〜3 フレーム）
- `DrawMarkers` の引数の検査の `Enum.IsDefined(style.Shape)` を、名前の比較に置き換えると、同じ条件の 6 回すべてで 0 B になった
- `Enum.IsDefined` の列挙の表が、GC の後の最初の呼び出しで作り直されると読んでいる。置き換えで消えたことからの読みで、ランタイムのコードは読んでいない
- 注釈の検査（`PlotPlan.Annotations.cs`）にも `Enum.IsDefined` が 3 か所ある。Issue #400（992 B）の手がかりとして、その Issue に書いた
