# G6a: 軸の置き場所と二次軸の計測

行 G6a（Issue #234）の計測の記録。二次の独立したスケールと、主の軸の変換の軸を付けた場面の 1 フレームを、軸が 1 本だけの同じ場面と比べ、要件 P-1（1 フレームの p95 が 8 ms 以下）と照らした。要件 §5 の参照機で測った。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。測った後に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light`（軸・グリッド・軸のタイトルあり） |
| ワーカー | `PlotWorkerPool.Shared`（15 スレッド）。プロセスの優先度は High |
| データ | 1e9 行の系列 2 本。y は `float` のメモリマップのファイル（4 GB ずつ、一様な値 4 つの和 × 25、シード 5 と 6。ページキャッシュに載っている）、x は `UniformColumn`（0 から 1 刻み） |
| 場面 | **軸が 1 本**: 2 本の line を左の y に載せる。**二次軸**: 2 本目を `ScaleY2`（domain [0, 100]、右）に載せ、主の x に変換の軸（x / 1000、上）を付ける |
| 測る範囲 | 2 秒描いて温めた後の 300 フレーム。主の y の domain を毎フレーム変える（前もって作った 7 つの仕様を順に）。x は全体を表示する。CPU は `Render` の 1 回、GPU はフレームのタイムスタンプのクエリ、確保は `Render` の前後の `GC.GetAllocatedBytesForCurrentThread()` の差の和 |
| 回 | 場面の順に 1 回ずつを 3 回 |

## 結果

フレームは中央値 / p95（µs）。各欄は 1 回目、2 回目、3 回目。

| 場面 | フレームの CPU | フレームの GPU | 確保（300 フレーム） |
| --- | --- | --- | --- |
| 軸が 1 本 | 7,396 / 8,433、7,176 / 7,803、7,266 / 9,704 | 2,154 / 2,336、2,242 / 2,392、2,447 / 2,683 | 0 B |
| 二次軸 | 7,889 / 9,069、8,822 / 10,624、5,653 / 6,802 | 2,528 / 2,642、2,617 / 2,804、2,081 / 2,189 | 0 B |

- **二次軸の分**: 2 つの場面の差は回ごとの揺れの内にある（CPU の中央値は二次軸の場面が −1.6〜+1.6 ms、GPU は −0.4〜+0.4 ms）。二次のスケールの系列は、主と別の M4 の組（§4.8）で、1 回の取り出しで主の組と並べて走る
- **最初の実装**: 二次の組を主の組の後に別の `Extract` で走らせていて、二次軸の場面の CPU が中央値 10.1〜11.2 ms、p95 11.8〜15.7 ms（軸が 1 本の場面は 5.6〜6.9 ms と 6.9〜9.6 ms）だった。1 系列の取り出しは呼び出し側かワーカーの 1 つの仕事で、全体の表示の 1e9 点で数 ms かかる（`docs/benchmarks/s2-e2e.md`、p50 3.55 ms、p95 5.04 ms）。1 本の y では 2 本の系列が 1 つの組で並んで走るが、組を分けると順に走って約 2 倍になっていた。プールに組を並べて 1 回で取り出す口（`ExtractTogether`）を足し、上の値になった
- **P-1 との比べ**: 軸が 1 本の場面でも、p95 が 8 ms を超える回がある。1e9 点の系列 2 本を毎フレーム全体で表示する場面で、取り出しが p95 を決める（行 S2 の記録の、全体の表示の抽出と同じ形）。行 G6a で増えた分ではない
- **GPU**: 2 つの場面で同じ桁で、軸の線・目盛り・ラベルが増えた分は揺れの内。系列の値は一様な値の和で、どの画素列も値の範囲の大部分にまたがるので、線がパネルの大部分を覆う。行 S2 のランダムウォークの場面（GPU の p95 0.18 ms）とは描く画素の量が違い、比べない
