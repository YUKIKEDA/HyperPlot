# G5b: Stat の計測

行 G5b（Issue #218）の計測の記録。設計書 §5.5.3 の Stat の仕事（bin・count・summary・quantile の radix select）を 1e9 行で、ホストと同じ形（`HeadlessRenderer`、ハードウェアの D3D11）で測り、要件 P-2（構築は 1 GB/s 以上）と P-1（1 フレームの p95 が 8 ms 以下）と比べた。要件 §5 の参照機で測った。

## 条件

| 項目 | 値 |
| --- | --- |
| 機械 | 参照機（要件 §5）: Core i5-13400F、GeForce RTX 3060 Ti、Windows 11 |
| ビルド | NativeAOT の Release（スクラッチのハーネス、この PR の作業ツリー。カテゴリの番号から列を作る internal の口を使うため、データの道のハーネスの名前を借りた。測った後に消した） |
| 描画先 | 1,920 × 1,080、ハードウェア、倍率 1、`Theme.Light` |
| ワーカー | `PlotWorkerPool.Shared`（15 スレッド）。プロセスの優先度は High |
| データ | 1e9 行。値は `float` のメモリマップのファイル（4 GB、一様な値 4 つの和 × 25、シード 5。ページキャッシュに載っている）。カテゴリと群は `int` の番号（4 GB）で、行 i の番号は (i + s) · 2654435761 mod n |
| 場面 | **ヒストグラム**: 値の bar と `Stat.Bin(maxBins: 50)`、1 群と、群 8 つを `ColorBy`（既定の積み上げ）。**count**: カテゴリ 50 と 1e5 の bar と `Stat.Count`。**summary**: カテゴリ 50 の errorbar と `Stat.Summary(Min, Max)`。**quantile**: 同じ errorbar と `Stat.Summary(Quantile(0.25), Quantile(0.75))` |
| 測る範囲 | **最初の描画**: 新しい計画で最初の `Render`（Stat の仕事と 1 フレーム）。**作り直し**: 値の列を `Invalidate` した直後の `Render`（3 回の中央値）。**フレーム**: 2 秒描いて温めた後の 300 フレーム（y の domain を毎フレーム変え、記録をやり直す）。CPU は `Render` の 1 回、GPU はフレームのタイムスタンプのクエリ、確保は `GC.GetAllocatedBytesForCurrentThread()` の差 |
| 回 | 場面の順に 1 回ずつを 3 回 |

## 結果

ワーカーの仕事はミリ秒、フレームは中央値 / p95（µs）。各欄は 1 回目、2 回目、3 回目。

| 場面 | 最初の描画 | 作り直し | フレームの CPU | フレームの GPU | 確保 |
| --- | --- | --- | --- | --- | --- |
| ヒストグラム（1 群） | 2,549、2,581、2,455 | 1,593、1,564、1,551 | 215 / 278、215 / 428、210 / 289 | 173 / 180、172 / 176、174 / 179 | 0 B |
| ヒストグラム（8 群） | 2,634、2,713、2,636 | 1,675、1,614、1,622 | 269 / 374、368 / 543、246 / 287 | 174 / 176、173 / 184、174 / 186 | 0 B |
| count（カテゴリ 50） | 125、158、121 | 1、1、1 | 215 / 335、241 / 399、200 / 235 | 192 / 194、191 / 194、192 / 196 | 0 B |
| count（カテゴリ 1e5） | 351、364、279 | 2、3、1 | 1,026 / 1,600、989 / 1,620、940 / 1,495 | 301 / 310、331 / 339、303 / 309 | 0 B |
| summary（最小・最大） | 1,715、1,527、1,465 | 1,331、1,489、1,285 | 203 / 261、202 / 246、207 / 250 | 192 / 194、191 / 194、194 / 198 | 0 B |
| quantile（2 つ） | 8,167、9,681、9,276 | 9,193、9,425、8,565 | 254 / 336、196 / 218、357 / 443 | 191 / 196、194 / 197、192 / 194 | 0 B |

- **ヒストグラム**: 作り直しは約 1.6 s で、値 4 GB（8 群は番号と合わせて 8 GB）を読む。1 群で約 2.6 GB/s、8 群で約 5 GB/s と、要件 P-2 の 1 GB/s を超える。仕事は、列の統計（区切りの範囲）と、区切りを数える 1 度なめ。最初の描画の約 1 s 多い分は、ファイルの最初の読み出しと、計画を作る仕事
- **count**: カテゴリの列は不変なので、値の列を `Invalidate` しても作り直さない（1〜3 ms は描き直しだけ）。最初の描画は番号 4 GB を 1 度なめて 0.1〜0.4 s（カテゴリ 1e5 は数の配列が大きく、L2 に収まらない）
- **summary**: 値と番号の 8 GB を 1 度なめて約 1.3〜1.5 s（約 5.5 GB/s）
- **quantile**: 約 8.2〜9.7 s。summary の 1 度なめ（値の数）と、`float` の 4 バイトの radix select の 4 段で、8 GB を 5 回なめる（約 4.4 GB/s で、1 回あたりは P-2 を超える）。順位の数 × セルの数のヒストグラム（4 × 50 × 2 KB = 400 KB）は小さく、時間はなめる回数で決まる。`double` の列なら 9 回になる
- **フレーム**: どの場面も、描くのは区切りかセルの数（50 区切り × 群、50 か 1e5 カテゴリ）だけで、P-1 に収まる。カテゴリ 1e5 は band が 1 画素未満で、画素列ごとにまとめる道（行 G7b）
- **作り直しの条件**: 最初の実装は、y の domain が変わるたびに bin の層を作り直していて、ヒストグラムの 1 フレームが 6〜9 ms で確保もした（2e6 行の試し）。bin は x のスケールの空間で決まるので、作り直すのを x の空間が変わったときに限り（§4.8）、上の値になった
