# ADR 0002: 密度タイルの時間と `DensitySplit`、要件 P-15 の範囲と条件

- **Status**: 採用。ADR 0001 の Decision 1 の「ほかのプロセスが CPU を使っている機械でも満たす」を置き換える
- **Date**: 2026-11-11
- **Issue**: #413（行 C3b）

## Context

行 C3b は、空間タイル索引に密度タイルを足した。構築は、確定のスナップショットを公開した後に密度タイルを作り、`Completion` はその後に終わる。ADR 0001 の P-15 の値（一様 75 秒、塊 180 秒）は、密度タイルのない行 C3a の `Completion` までの実測から決めたものである。計測は `docs/benchmarks/c3b-density-tiles.md` にある（1e9 点、1 周と `DensitySplit` の比較、16 回の構築）。

- 密度タイルが付くまでの時間（確定の公開から）: 一様 3.17〜4.62 秒、塊 4.72〜5.89 秒
- 表と密度タイルの合計: `DensitySplit` が 2^17 で一様 4.68 %・塊 4.59 %、2^18 で 1.33 %・2.80 %、2^19 で 1.33 %・2.02 %。どれも要件 P-8 の 10 % 以下で、上限で止めた水準はない。作る時間は、どの値でも上の幅の中である
- 計測の間、ほかのプロセスが平均 4.5 コアを使っていた。確定の公開までの時間は、一様 57.4〜82.1 秒、塊 153.7〜180.8 秒で、P-15 を超えた回が 2 回あった（ほかのプロセスが 5.6 コアと 3.4 コアの回）。行 C3a の最後のコミットと交互に走らせた比較（1e8 点、24 回ずつ、中央値 3.39 秒と 3.29 秒）では、行 C3b の変更による差はなかった

## Decision

1. **P-15 の範囲**: 75 秒と 180 秒は、点を問い合わせられる確定のスナップショットの公開までの時間である（オーナーの決定、2026-11-11）
2. **密度タイルの時間**: 確定の公開から密度タイルが付くまで、どちらの分布も 10 秒以内。実測の最大（5.89 秒）に余裕を置いた 1 つの値である（オーナーの決定、2026-11-11）
3. **`DensitySplit`**: 2^18 のまま。2^17 はメモリが 1.6〜3.5 倍になり、それが要るという数字がまだない。描画で値を見直す必要が出たら、行 R3 で測って変える（オーナーの決定、2026-11-11）
4. **P-15 の条件**: 値は変えず、「ほかのプロセスの CPU が 2 コア以下の参照機」での値と要件に書く。ほかのプロセスが 3.4 コア以上を使う機械では、超えることがある（実測の最大は一様 82.1 秒、塊 180.8 秒）。ADR 0001 の「ほかのプロセスが CPU を使っている機械でも満たす」は、行 C3a の計測の状態（塊で 2.3〜3.9 コア）にだけ当てはまる文で、ここで取り消す（オーナーの決定、2026-11-11）
5. **負荷のあるときの動き**: 裏の構築が利用者のアプリとほかのプロセスに CPU を譲ること、その逆にほかの負荷が構築を遅らせることは、行 S4（Issue #414）で、要件の項目から決める

## 退けた案

- **P-15 を密度タイルまで含めて 75 秒・180 秒にする**: 一様の余裕が数秒に減る。確定の公開で点の問い合わせはできるので、密度タイルは別の値にした
- **密度タイルの時間を一様 6 秒・塊 8 秒にする**: 負荷のある機械では超えうる
- **P-15 を 90 秒・200 秒に緩める**: 静かな機械で遅くなっても気づきにくくなる
