# ADR 0004: 3D の線は postpass、印は half で深度と合成する

- **Status**: 採用
- **Date**: 2026-11-14
- **Issue**: #513（行 K1 の試作）。設計は #509（決定 3）と PR #520

## Context

行 K1 は、3D の折れ線（`DrawPolyline3D`）と印（`DrawMarkers3D`）を深度つきで描く。2D の折れ線は 3 パスで描く（被覆を `R8` のテクスチャに MAX で取り、色を 1 回で塗り、0 に戻す。設計 §5.3）。1 本の折れ線は 1 つの色で 1 回だけ塗るので、線分ごとの深度をどこにどう書くかは自明でない。印の縁は被覆で混ぜるので、深度を書く範囲も決まっていない。Issue #509 の決定 3 は、この 2 つを試作で比べて決めるとした。

試作（ブランチ `spike/509-depth`、`benchmarks/HyperPlot.Depth3D`）は、線を 7 つ、印を 4 つの方式で描き、CPU の参照（1 画素を 16 × 16 で標本にした z-buffer）と比べた。誤差は画素ごとの R・G・B の |GPU − 参照| の最大（0〜1）で、参照で図形の標本を持つ画素から 3 × 3 の近くの画素（触れた画素）で数える。機械は参照機（Core i5-13400F、RTX 3060 Ti）、NativeAOT の Release、1,920 × 1,080、seed 1。記録と再現のコマンドは Issue #513 の `## Result` にある。

## Decision

1. **線は `postpass`**（Issue #513 の決定 1）: 折れ線ごとに、被覆のパス（深度を `LESS_EQUAL` で検査し、書かない）、色のパス、0 に戻すパス、深度のパス（画素の中心の被覆が 0.5 以上の所に `LESS_EQUAL` で深度を書く）の順に描く。誤差 0.5 を超える画素が、どの場面でも最も少なかった（42〜125 画素、触れた画素の 0.03 % 以下）
2. **印は `half`**（同決定 2）: 1 回の呼び出しの印をすべて 2 回描く。1 回めは被覆が 0.5 以上の画素を混ぜて `LESS` で深度を書き、2 回めは 0.5 未満の縁を検査だけで混ぜる。誤差 0.5 を超える画素は 0〜38 だった（`touched` は 1 万〜2.8 万）。Issue #477 の 3D の点にも使う
3. **許容差は統計の上限**（同決定 3）: 線は平均 0.05・p99 0.35・0.5 を超える画素が触れた画素の 0.05 % 以下、印は平均 0.08・p99 0.35・0.01 % 以下。触れた画素の外の誤差の最大は、線が 0.07 以下、印が 0.16 以下（同決定 6。深度を広く書きすぎて面を隠す退行を見つけるため。退けた `quad` は 0.50〜0.60、`uav` は 0.29〜0.35 だった）。どれも WARP の最も悪いフレームを切り上げた値である（触れた画素の外は線 0.063、印 0.149）。最大は 1 画素で決まる（線で 0.87）ので使わない。決定性は SHA-256 で別に確かめる（設計 §10）
4. **しきい値 0.5**: 試した唯一の値で、ほかの値とは比べていない
5. **選んだ理由は精度**（同決定 5）: `postpass` は深度なしの 2.2〜3.0 倍の GPU 時間がかかるが、1e6 線分の p99 は最大 4.87 ms で、16.7 ms の予算に収まる。被覆のパスの調整は、行 K1 の実装の計測（設計 §9 の「3D の小さい道（行 K1）」）で見る

## たどっていないもの

Issue #513 の決定 5 で、次の 3 つは原因をたどらずに記録する。1 と 2 は行 K1 の実装の計測で、3 は Issue #477 で追う（同決定 7）。どれも方式の選択（精度で選んだ）を変えない。

1. **深度の検査つきの被覆のパスが重いこと**: `postpass` の被覆のパスは `none` の 1.42〜1.43 倍（結び目）と 2.40〜2.45 倍（酔歩）、深度のパスのない `test` では 3.7〜3.9 倍だった。`SV_DepthGreaterEqual` の出力と `LESS_EQUAL` の検査のどちらがどれだけ増やすかは分けていない
2. **色と 0 のパスが 2 つの群に分かれること**: フレームごとの値が 0.2 ms 未満と 0.2〜0.83 ms に分かれ、`test` の酔歩の 6 回のうち 3 回で p50 が 0.28〜0.29 ms になった。`postpass` の p50 には出ていない。行 K1 の実装の計測（設計 §9 の「3D の小さい道（行 K1）」）で、パスごとの時間のフレームごとの分かれ方として見る
3. **ハードウェアで 1 ulp 違う 2 つの深度の前後が入れ替わること**: 印の結び目 10 px の frame 0 で、ハードウェアだけで 0.5 を超える 24 画素は、続けて描く 2 つの印の深度が float の 1 ulp（約 6 × 10⁻⁸）しか違わない所だった。ハードウェアは参照と WARP と逆の印を手前にした（頂点の変換か深度の補間かは分けていない）。ハードウェアの 2 回の SHA-256 は一致し、over_0.5 は 0.0086 % で印の上限に収まる。Issue #477（3D の点の試作）で追う（Issue #513 の決定 7）。深度が 1 ulp しか違わない印が並ぶのは点が密なときで、WARP の試験には出ない

## 退けた案

- 線の `none`（深度なし、描く順のまま）: 描く順の誤りが最も多い（結び目で over_0.5 が 5 万画素）
- 線の `test`（被覆のパスだけを検査し、深度を書かない）: 線どうしの前後が `none` と同じく誤る。面を後に描くと `none` と同じ画像になる
- 線の `prepass`（深度のパスを 3 パスの前に置く）: 自分と交わる所の継ぎ目で誤差 0.25 を超える画素が多い（結び目で 36,980〜50,695）。平均は `postpass` の 2.6 倍
- 線の `capsules`（線分ごとに被覆を混ぜて深度を書く）: 続く線分の重なりで 2 回混ぜ、max 0.945、over_0.5 が結び目で 4 万画素
- 線の `uav`（被覆のパスで最小の深度を UAV に取り、色のパスで画素ごとに検査）: 面と交わる所の帯で over_0.5 が結び目で約 3,000、触れた画素の外にも誤差が出る（0.29〜0.35）
- 線の `uavfrag`（`uav` の検査を断片ごとに）: over_0.5 が結び目で 1,256〜1,848、`postpass` の 10 倍を超える
- 印の `none`: どの場面でも over_0.5 が最も多い（一様 10 px で 22 万画素）
- 印の `quad`（四角全体に中心の深度を書く）: 深度を書く方式で over_0.5 が最も多く、面を後に描くと四角の角が面を隠す（0.50〜0.60）
- 印の `touched`（被覆が 0 より大きい所に書く）: 縁が後の印を隠し、over_0.5 が 1 万〜2.8 万画素
- 許容差を WARP のバイト一致のゴールデン画像にする（Issue #513 の決定 3）: 無害なシェーダの変更でも壊れる
- 触れた画素の外の誤差に上限を置かない（同決定 6）: 深度を広く書きすぎる退行を試験が見つけられない
- 1 ulp の深度の入れ替わりを行 K1 の §9 の項目で追う（同決定 7）: 行 K1 の印は 131,072 個までで、密な点は八分木の行で描く
- 設計 PR の前に、シェーダの変え種（深度の出力なし、`SV_Depth` と `SV_DepthGreaterEqual`）で上の 3 つの原因をたどる（同決定 5）
